# 组件选择与素材流程

[组件目录](../config/components.json)是标准组件的唯一目录：每个条目包含 `name`、`description`、`html`，另有两个可选字段——`shapes`（该组件登记过的呈现形态名与选择器，承载登记卡的形态语义）和 `placement`（值为 `catalogue` 时只登记造法，见下）。`html` 是供 LLM 复制、阅读和修改内容的标准实例，不是等待工具填充的插槽模板。本文不复制实例 HTML、CSS 或尺寸规格。

## 如何选用目录

- **先看本页意图与配方登记卡**：骨架级配方直接复制对应骨架档（组件、件数、排布已由骨架定死）；规格级配方按登记卡绑定行就地组装。[配方目录](../config/recipes.json)的区域 `allow` 是装配的兜底白名单，不是组件选择菜单。
- **再看组件语义**：阅读允许组件的 `description` 与 `html`。组件选谁、放几个，由登记卡绑定行与骨架结构在设计期定死；登记卡未绑定的自由槽位（规格级组装、`free` 页）按本行方法在区域 `allow` 内装配，条数落在登记卡绑定区间内。目录里标了 `placement:"catalogue"` 的组件只登记造法，能不能放到本页只看所选配方的区域 `allow`，不看目录里有没有登记；放进不允许的区域按 L11 报错。
- **复制实例再替换**：保留标准结构与类名，换入真实文案、图片及本页语义标记。示例文字、示例图片和示例 ID 不是当期内容，不能原样充作事实；实例里占位的图标字符同理——图标位放的是从该条信息提炼出的一个字。标签条目 `cr` 的标签下可另挂一行英文小标签 `.en`，它是可选项，但一旦放上去就是内容字段，要有自己的 `data-layer` 与 `data-from`，不能当装饰省掉来源。
- **排列直接写 HTML**：按[技术契约](02-constraints.md)组合布局容器与区域。骨架档的条数由骨架 `repeat ×N` 注释与登记卡绑定区间定死（装配按注释展开）；规格级按登记卡绑定区间装配，实例给了几条不代表区间上限，增减条目须落在绑定区间内并分配新 ID，不依赖组件目录里的自动重复机制。组件下限与形态承诺由配方登记卡绑定字段承载（⚠️ C2 拆分第五刀（2026-11-13）起 gate 的 require/form 检查退役，config 的 `require`/`form` 字段与加载期写法校验已随之删除，装配自查+人审兜底）——条数与排布是设计期决策，生成期照卡照骨架装配。
- **步骤连成时间线**：顺序型内容用步骤组件，条数照流程走。需要一条贯穿的脊柱时把 `.timeline` 写在步骤所在的区域上，编号列、竖线与圆点由种子给出，不在本页重画；步骤横向排还是纵向排、要不要脊柱都由本页信息结构决定。
- **外观不由本页决定**：颜色、字体、边框与质感的唯一来源是种子，规则见[技术契约](02-constraints.md)；布局有需要时只调整实例尺寸、排列和图片窗口。这条不是口头约定：本页 `style` 里写外观属性（`color`、`background*`、`font*`、`border*`、`box-shadow`、`filter` 等）或改写 `--种子变量` 会被静态检查 L17 判错，布局、尺寸、间距、定位、裁切与构图照常开放。
- **强调按内容选**：`hl` 只标出最需要被记住的那一处，任何页的 `h1`、`sub` 都能用，不是封面专属；标题区（引题、主标题、副标题合起来算）最多一处，页尾的收束金句另计一处，再多就按没有重点处理；没有值得强调的词就不加。标题区加不加高亮是排版判断，检查器不强制；所选配方登记卡若点名了 `marked` 形态，引语内就应有一处 `.hl`——⚠️ C2 拆分（2026-11-13）起 gate 不再拦（原 L11③ 退役），归登记卡绑定字段，装配自查+人审把关；点名以登记卡为准。副标题本身是弱色，命中后要加粗才读得出层级，这条已由种子给出。
- **金句按形态立住**：整页金句用 `serif` 的 quote 组。每种形态的选择器与说明都只登记在[组件目录](../config/components.json)的 `shapes` 里，登记卡点名本页用哪种；本页照点名的形态补齐结构，缺哪一项就是那一维没做到，不是把字号随手调大。省出处时连分隔线 `.rule` 一起省（登记卡耦合约束，装配自查+人审）：留一根没有出处的横线只是装饰噪音，与目录"不为一根线补假出处"互为表里。
- **排法是设计期决策，装配照档走**：齐列还是 `.stagger` 错落（封面与内页同样适用）、旁注要不要引线（引线版写在旁注自己的类上，需要一条引线指向旁边的画面时用）、对比横排还是上下叠（上下时在两块之间放一个骑缝标记 `.vs`——它和引题下那道分隔线一样只是装饰，不登记内容），都已由骨架档或登记卡显式登记；装配照档取用，不在生成期即兴重排。这些都只改区域或容器上的类名，不改结构与标记。
- **整幅与行内由区域布局决定**：占满整行（整幅）的条目用编号条目、列表条目、标签条目或正文；浮动卡片是行内浮层（种子限宽 42cqw），适合在分栏里与画面并排或用 `.stagger` 错落——这是区域布局的选择，不是组件之间的强制搭配。手机有种子保底的最小高度，区域给不出就是布局问题：换更宽的区域、减少同区内容或减并排数量，不压扁壳、不拉伸画面。
- **引语档位跟着空间走**：区域内的收束引语用 quote 组默认档（种子字号与正文同档、不放大）；hero 大字档只给整页一句话的金句页。区域引语放大就会挤占画面、压小同页手机、与标题抢主角——一页出现两个大字块先降档或删一个。
- **弱档与变体走类名，不走内联**：L17 封死了内联改色改字，次要说明要降一级时用 `text-block` 的 `.muted` 弱档（种子给的 muted 色与更小字号），不是把正文档内联调小调淡。组件的呈现变体（截图的 contain/fill/inset、旁注的引线版、对比的 before/after、勾选态、弱档正文等）都登记在目录 `shapes` 里：登记卡绑定点名的形态照卡装配，卡没绑的即装配自由档；实际用了哪种变体写进 plan `intent` 让目检可核对是刻意还是遗漏（如勾选态全选要说明理由），不为消掉留白提示堆变体。
- **背景大字落在 overlay 区域**：`ghost` 只承载装饰字符，放在 `overlay` 区域，且该区域必须是 `.p-page` 的直接子级（**L21** 拦截）——ghost 的右缘/底边锚的是最近定位祖先，落进正文区会随区域漂移。overlay 只有非封面配方开放，内页用不用由本页决定。

组件选择看信息是否适合，而不是“还差几个块”：

| 内容特征 | 选择方向 |
|---|---|
| 功能与收益 | 功能卡、特征行或文本块；不要把界面当前状态直接改写成长期承诺 |
| 同级要点 | 清单或条目；勾选表达真实语义，不为填满视觉默认全选 |
| 操作过程 | 步骤；顺序来自实际流程 |
| 有口径的数据 | 数据行或图表；单位、标签与结论一起可核对，图形比例不得夸大差异 |
| 前后或选项差异 | 对比组件；保留比较条件，不强行凑成对称字数 |
| 引文、补充说明、下一步 | 引语、旁注或收束组件；无补充信息就省略 |
| 真实产品界面 | 整屏竖屏截图用手机，局部界面、横图和照片用截图组件；按素材形态和本页证明目标选择 |

这些只是选用方向，不是第二份组件白名单；最终可用项以配方和组件目录为准。需要某种内容但没有适合组件时，先用允许的简单表达或调整页面目标，不在生成任务里擅自扩充规范。

## 图片素材流程

**查看 → 登记 → 选择载体 → 调整窗口 → 检查实际页面。**

- 查看要使用的原图，确认它能证明什么，检查关键文字、主体和隐私信息。真实 UI 是证据，不用 HTML 或生成图片冒充截图。
- 在池的 `asset_meta` 登记素材类型与真实宽高；工具不代读尺寸，用系统图片信息或浏览器读一次填入。文件使用可理解的名称，复制到 `out/assets/`，保留来源；字段定义见[内容提炼](01-content-refinement.md)。
- 不强制转码。按透明度、文字清晰度、体积和兼容性决定是否压缩或转换，保留原始素材，不以省空间为由删除用户原图。
- 先看 `asset_meta` 登记的类型与真实宽高比：竖长接近手机比例、内容是完整一屏的，用手机组件，沿用目录中的截图与壳层次；局部 UI、横图和照片不硬塞手机，改用截图窗口或其他允许载体。
- 壳与窗口的大小写法以目录实例和种子为准，多只并排时按目录实例改成宽度驱动。区域放不下就是布局问题，换区域、减少同区内容或换载体，不压扁、不拉伸。需要大画面贴边时按技术契约的出血两步走，不手动把壳拖出画布；贴到右下角那种向下出血要按契约把页码省掉，让画面压不进页脚文字。
- **同一区并排多只手机时，每只下方标一行界面名**：外层 `.phone-cell` 包住壳和一个 `text-block`，小标题是壳的兄弟节点——这是配方登记卡的绑定纪律，装配自查+人审把关（C3 起 gate 不再强制）。真正的硬错误是把文字塞进手机根内：锁高（inline `height` 非 `auto`）的 `phone` 根自带素材比例，塞进文字叶会压坏壳体画面，静态检查 **L19** 拦截——锁高壳内不得出现任何 `data-editable="text"` 文字叶，所以这里不能照搬截图窗口的内部图注写法。单机时注解尽量省；需要时走 `.phone-cell` 小字档或 `.text-block.muted` 弱档，不用全强度正文档抢主体。
- 截图窗口的形态按目录实例的说明选：默认只做等比容纳，带底与描边和铺满裁切各有自己的变体。选哪种由画面决定，不由"看起来空"决定，也不靠补底色、补边框掩盖素材与窗口的比例不符。
- 需要方形或指定比例时，`aspect-ratio` 与 `flex` 写在窗口本体（`figure`）上，不要给 `<img>` 钉死某一维为 0：种子已让 `.shot>img` 靠 flex 撑满，再把 `<img>` 高度写 0 会量出 0 高的塌陷画面，`<img>` 被可见性过滤摘掉后其余几何检查全部静默跳过。画面塌陷由检查器 R11 单独判为硬错误，负例应实际失败。在 `flow-grid` 这类由内容决定高度的栅格里，这条必须执行——窗口不带 `aspect-ratio` 就会在栅格单元里塌成 0 高。
- 种子布局原语提供两列与三列两档：`.flow-grid` 默认两列，加 `.three` 得三列；更多列不预设，按同一规则在窗口本体写。要把多列证据（数字、画面窗等）拼进同一张卡面时，容器加种子 `.panel`——它只给底色、描边、圆角与阴影，内边距与分栏比例仍由页面用布局属性写（质感属性出现在内联样式里会被 L17 拦下）。比例声明要与素材真身一致——宽幅选横图、竖幅选长图，`fill` 只做微调裁切，不把竖幅长图硬裁成横带。出血是**区域级**布局档：区域挂 `.bleed`（左右贴到画布边），区内图窗用 `fill` 铺满——出血不要挂在图窗上（负边距会让组件几何越出区域，被 R1 拦截）；出血区域必须配一处标题或说明文字（head 或 bottom），不允许整页只剩图。这条由静态检查 **L23** 执行：出血区内部的图注不作数，head 或 bottom 里至少要有一个可见文字叶。
- 需要整图信息时尽量保持完整；需要强调局部时用图片窗口、`object-fit` 和 `object-position` 调整。等比处理，不拉伸造假，不裁掉使结论成立所必需的上下文。
- 图注属于图片组件内部。图注和旁注都要说出本图真正支持的信息，并引用内容资产；不要在图片组件内嵌另一个内容组件。
- 构图受阻时可换素材、改窗口或换允许组件，再看本轮截图是否清楚。不能为消除留白提示补虚假截图、数字或没有信息的卡片。

## 缺图与补图

素材不足时优先使用已有事实的文字或数据表达，不因无图卡住整个流程。图像对任务确实重要时，按用户要求请求素材或使用获准来源，记录出处与使用许可。

生成图或通用图库可作明确的示意、氛围素材，不能充当真实产品 UI、用户评价或事实证据。是否需要确认取决于用户目标与素材风险，不限制为某个固定确认次数。
