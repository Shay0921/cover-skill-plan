# 内容提炼与轻量计划

本文只管内容判断、`02-pool.json` 和 `03-plan.json`。HTML 与标记见[总限制](02-constraints.md)，素材使用见[组件用法](03-components.md)。两个文件与源页面**没有先后要求**，可以同一轮写出；gate 只在运行时要求三件齐备，并做 `data-from ↔ uses ↔ pool` 三向对账（双向：页面引用必须在 `uses` 里，`uses` 列的必须真被页面引用）。

## 从素材到可读内容

- **先理解，再取舍**：找出读者、场景、核心主张及支持它的证据。截图上的当前状态不自动等于产品能力，更不等于效果承诺。
- **表达具体而真实**：用动作、场景和有依据的结果说明价值。短句便于扫读，但不为整齐排比删掉条件、否定词或适用范围。
- **钩子要兑现**：可从痛点、好奇、利益、身份或数据切入，按需要比较少量候选；不设候选配额、星级门槛。标题与卡面可以互补，不必机械套用不同钩型。
- **数据与引语可核对**：不编造功能、案例、数字、评价或引文。换算须将原值、单位、公式与结果记入证据；改写的观点不能冒充逐字引语。上版文字与资产 `text` 的关系按[总限制](02-constraints.md)的来源分级校验执行：`data`/`quotes` 逐字，其余可润色但保留可回溯的重叠。
- **确认服务于任务**：按用户要求确认内容；对能从素材判断的事不反复提问。未证实的断言先核实、弱化或删去，用户认可文案也不等于事实已获证明。

## 内容池：`work/02-pool.json`

保留以下分类，无素材的数组可以为空，不为填字段补内容。

| 字段 | 含义 |
|---|---|
| `thesis` | 核心主张，资产对象 |
| `highlights` | 亮点、能力、收益或解释，资产数组 |
| `pains` | 有依据的场景与问题，资产数组 |
| `hooks` | 卡面或标题的选用表达，资产数组 |
| `data` | 带单位、口径和解释的数据，资产数组；上版文字逐字取自 `text` |
| `quotes` | 可核对的引文或明确标为改写的观点，资产数组；上版文字逐字取自 `text` |
| `asset_meta` | 图片文件名到元数据的映射；有图时填写 |

每个内容资产统一保留：

- `id`：池内唯一且稳定的引用标识，例如 `h1`、`d1`；它不是组件名，也不随页面顺序变化。
- `text`：准备上版的表达。标题、说明、图注等需要独立使用的表达也可作为资产登记，无需为每条亮点预制一套短语菜单。
- `evidence`：支撑这句话的原文段落、截图位置、数据口径或换算依据。不能只写“见素材”而无法核对。
- `source`：实际出处，如文件名与段落、图片名、链接及引文作者。AI 改写要注明是改写及所依据的来源，不能将“AI 补充”当作事实证据。
- `paraphrase`（可选）：仅 `true` 有效，表示这条资产的上版文字是明确标注的改写。检查器对 `data`/`quotes` 的文字不符降为告警而不判硬错误；不写或写其它值一律按逐字要求处理。

图片记录 `kind / w / h`：`kind` 使用 `phone-screenshot`、`ui-crop`、`photo` 或 `other`；宽高填实际像素尺寸，当前工具不会代读也不会回填，用系统图片信息或浏览器 `naturalWidth` 读一次即可，不必手工估算精确值。暂未读到尺寸时先缺省，使用前补上，不填假值。分类只是素材事实，不自动决定组件或裁切方式。

以下仅示意字段形状，文案、来源与尺寸须换成当期真实内容，示例数值不是对当期素材的测量：

```json
{
  "thesis": {
    "id": "thesis",
    "text": "当期核心主张",
    "evidence": "支撑主张的具体原文",
    "source": "原文文件与段落"
  },
  "highlights": [
    {
      "id": "h1",
      "text": "当期亮点的上版表达",
      "evidence": "能证明该亮点的原文或截图位置",
      "source": "实际素材出处"
    }
  ],
  "pains": [],
  "hooks": [],
  "data": [],
  "quotes": [],
  "asset_meta": {
    "detail.png": { "kind": "ui-crop", "w": 1080, "h": 1920 }
  }
}
```

候选表达在取舍阶段比较，决定上版的才落池；不强制记录全部淘汰过程。写页面时允许继续润色，但 `data`/`quotes` 的上版文字须与资产 `text` 逐字一致或取其连续片段；改这两类文案、增加数字或改变单位口径时先同步更新资产与证据，需要改写的加 `paraphrase: true`。其余类别的实质改写同步维护池与 `uses`，保持页面可回溯。登记进池的每条资产（`thesis` 除外，它是核心主张、不直接落上画布）都要被某一页的 `uses` 引用；没页用到的就是孤儿文案，要么删掉，要么给它找到用法，不留只登不用的条目——计划加载时发现孤儿资产直接报错。

## 页面计划：`work/03-plan.json`

先确定每页要传达什么，再从[配方目录](../config/recipes.json)选配方。页数按信息量、图片可读性与阅读节奏决定；不强制固定页数或指定首末页配方。

```json
{
  "meta": { "style": "paper-journal", "issue": "", "brand": "当期品牌" },
  "pages": [
    { "nn": "01", "recipe": "R-card-01", "intent": "让读者看懂核心亮点", "uses": ["h1"] }
  ]
}
```

| 字段 | 契约 |
|---|---|
| `meta.style` | 所用风格，当前为 `paper-journal` |
| `meta.issue` | 用户给定或已确认的期名；没有就写空字符串，键不能省略。只有封面系列配方把它排上页眉，内页不显示期号 |
| `meta.brand` | 当期真实品牌或署名，键不能省略，**也不能是空字符串或纯空白**——空值在计划加载阶段就被拒绝。没有品牌时给一个当期真实署名（例如本页主题）；画布 `.brand` 文字必须包含 `meta.brand`，不一致被静态检查 L6 判硬错误；也不冒用其他品牌 |
| `pages[].nn` | 两位页码，对应 `work/src/pNN.part.html` 与 `out/NN.html` |
| `pages[].recipe` | 配方 ID；决定可使用的区域、各区 `allow`/`max`，以及配方的 `require` 下限与 `form` 形态要求 |
| `pages[].layout` | 构图骨架档：配方登记了 `layouts` 时必须显式选一档（如 `A`/`B`）或写 `"free"`，没有骨架时只能缺省或 `"free"`（与 `dark` 同一纪律，让目检分辨刻意自由与忘了选档）。它锁的是几何区间（列宽比例、载体宽度档、标题行数、件数、锚点），不锁组件选择与文案；字段含义与校验见[技术契约](02-constraints.md)「构图骨架」 |
| `pages[].intent` | 本页的内容目标，不是布局指令 |
| `pages[].uses` | 本页实际使用的池内资产 ID；每个普通内容文本的来源须在这里 |
| `pages[].dark` | 可选配色开关，只写 `true` 或省略；写 `false` 在计划加载阶段就被拒绝（检查器只认两种取值，留 `false` 等于允许计划与画布各说一套）。写了画布根就必须带 `.dark`，省略则不得带。它换的是同一风格的深色变量，不是配方，也不是另一套结构 |

> ⚠ 方向相反的两个字段，写计划时先核对：`brand` **禁止空字符串或纯空白**（加载期直接拒绝，没有品牌就写当期真实署名）；`issue` **必须写空字符串**（没有期名就写 `""`，键不能省略）。

`uses` 中的 `h1` 是资产 ID；组件目录也可能有同名组件，两者不可混用。计划不记录组件树、区域实例、坐标或编辑状态。实际排列与组件选择直接写在 HTML 中。

配方 ID 全部可用。每个 ID 的 `name`、`intent`、各区域的 `allow`/`max`、配方级的 `require`/`form` 与命名构图骨架 `layouts` 只读[配方目录](../config/recipes.json)，字段含义与校验规则以[技术契约](02-constraints.md)为准，本文不复制第二份说明——按本页要达成的事去比对 `intent` 选 ID，再按画面载体与几何条件选骨架档（或写 `free`）即可。

配方不是固定版面：区域可省略，区域内允许多个组件，顺序与分组由 LLM 决定；没有隐性每区一块或条数上限。能在允许集合内换组件就直接换，不为横排、竖排或换序新增配方。选了骨架档的页，几何要落在该档区间内（列宽比例、载体宽度档、标题行数、件数、锚点），但组件选择与文案仍由内容决定；骨架档不够用时换一档或写 `free`，不在生成任务里擅自改骨架数值。

### 选配方与定主角

- **主角决定配方**：先问本页的主角是画面、数据、步骤、对比还是主张，配方跟着主角换——主角是截图就选截图墙/画面页，主角是逐条数据就选数据账本，主角是一处细节就选旁注详情。次信息不另起配方，用所选配方区域内允许的组件动态承载；一页混多种信息时，只把最重的那种信息立为主角，其余降为辅助，主角不突出多半是配方没跟着换。
- **配方按 intent 选，不按页码顺延**：先写本页要达成的事，再比对目录里每条配方的 `intent`——讲透一处细节选旁注详情，逐行对账选数据账本，收拢主张并给出口选结尾。拿不准时把候选配方的 `intent` 与本页目标并排比对，语义重合的那条是对的；条目排布杂乱、抓不住重点，多数是配方选错，先换配方再调布局。
- **备选方案从目录推导，不另立清单**：按主角类型先从配方目录圈出候选集（画面→区域 allow 含 shot/phone 的配方；数据→含 bars/ldr/ledger；步骤→含 step；主张与观点→含 serif；差异→含 ba），再用 `intent` 从候选集收敛到一条。这样备选始终来自配方目录的当前数据，不产生会漂移的第二份对照表。
- **每页一个主角，也只立一个主角**：标题区的 `h1` 是全页唯一的超大字；正文区只有整页金句（quote 组 hero 档）才算第二主角，且只在该页只剩一句话时用。区域内的收束引语走 quote 组默认档，不与标题抢层级。bottom 区允许 `h1` 的配方可以把底部大字当主标题：用了底部标题就不再写标题区，全页 h1 仍只出现一处。一页出现两个大字块（如 h1 与大字号引语并列）就是没有重点：降级引语档位或删掉其一。
- **首末页不留整块空白**：封面与结尾除标题区和画面（手机/截图出血）外，剩余一侧要放允许组件承载内容（卖点卡、清单、正文、行动入口）。大片空白说明这页缺了一块内容：先回内容池找，找不到就把画面放大或合页，不为填空编内容。

## 内容侧自检

- 每个事实都能找到证据吗？截图是否真能证明文字所说的能力？
- 读者不看原文能理解短句吗？钩子的承诺是否在后文兑现？
- 各页是否有新的信息或作用，而非同一卖点换句式重复？
- 图片、数字与解释是否对应？删减是否丢了关键口径？
- 内容少时能否合页、删页或保留有意留白，而不是为了密度提示补虚假内容？本页主角信息是否值得单独成页——信息弱就合并，不为凑页数立弱主角？
- 长标题与引语的断行落在语义停顿（逗号、顿号之后）了吗？行首有没有出现标点？

内容判断由 LLM 负责；技术检查通过不等于事实或叙事已经正确。
