# 自由组合页规范

> 运行时规则文档：只写 AI 必须知道的流程、意图、人工判据与指针。机器能自检的枚举、阈值、取值集合不在此复述——以代码为准，报错会说准。

## 1. 什么时候用

三条版式来源按顺序判定，一页一判：

1. 有语义匹配的母版、槽位填得满 → 现成母版。
2. 匹配但槽位撑不满、**且必须保留该母版的私有结构**（专属类、手机展示族、专属图形、私有图槽定位）→ 即兴补空。
3. 槽位装不下、或没有匹配的母版 → **自由组合**（本文）。

内容本身装不下时回炉重提炼文案，不是换版式能解决的。自由组合不是某类题材的补丁，与母版是平等的版式来源；占比高说明这批内容形态各异，不是问题。同一形态跨页或跨任务反复出现时转正为母版。

## 2. 提交形态

```json
{ "nn": "03", "name": "两栏要点对比",
  "layout": "custom/composed-<语义名>",
  "layoutBase": "<语义匹配的母版类>",
  "markup": "<div class=\"artwork-page …\" data-artwork data-size=\"1080x1440\">…</div>" }
```

- `layout` 写成 `custom/composed-<语义名>`：语义名描述**版式结构**，不写内容主题、不写页码。带 `composed-` 前缀即按组合页处理，此时漏写 `layoutBase` 硬停、不降级成补空页；漏写前缀只 WARN（占比统计与人读靠它）。
- `layoutBase` 必填：从该风格 `catalog.md` 选一个能提供合适 `.content` 骨架的母版类，根类必须与之相同。合法取值由机器校验，写成不受支持的类会直接报错——不在此枚举，报错会列出可用值。

  放行集是**常量而非推导**：`style.css` 里有 `.content` 的骨架远多于做过副作用实测的，按「有 `.content` 就能借」推导会静默放行。借骨架前在 `style.css` 里搜「骨架类 `.content`」和该骨架对共享组件的覆写——填充相关的坑见 §4.1；另有两类机器不查、只能人读 CSS 的：

  - **共享组件被骨架改成通栏**（如 `.callout` 加了 `grid-column:1/-1`）：搬进去会撑满整行，想保留窄卡片就自己写宽度，别原样搬。
  - **共享组件被骨架改成深底**（如 `.tag` 挂了墨底）：浅底页上会突兀，需另行覆写。

  改 `style.css` 后要重测；新骨架按这两类加上 §4.1 的填充分型实测过、确认没有意外，再进常量表（常量表在代码里，不在本文）。
- `markup` 整页 HTML、文案写死，不写 `fields`。唯一可留的占位符是 `{{page-no}}` / `{{progress}}`，且必须挂在对应 `data-sys` 节点内；其余文案直接写进 markup。图按相对任务工作区的路径写 `<img src="shots/a.png">`，出图时自动转 base64；写了 `<img>` 就必须给图，无 src 硬停。
- `layout` 与 `layoutBase` 要自洽：前者说这是什么版式，后者说借谁的骨架。机器只查 base 在不在允许集、根类是否一致，**判不了语义**（三栏配两栏骨架它看不出来），这一项靠人审。

## 3. 页面结构

```
<div class="artwork-page <layoutBase>" data-artwork data-size="1080x1440">
  <div class="paper-noise"></div>   <!-- 网格底纹，永远第一个子元素 -->
  <div class="brand-top">…</div>
  <div class="after-hero"></div>    <!-- 可选：有超大标题时 -->
  <div class="content">…</div>
  <div class="pg-footer">…</div>
</div>
```

- 根三件套齐全，根上只挂一个母版类。四件套缺一不可、顺序固定。
- **系统槽惰性注入**：写了 `data-sys` 就由渲染脚本填，没写就跳过——不强迫带槽，但带了就与全篇同源，品牌改名、加删页自动跟随。`data-sys` 的合法取值、必填节点形态由校验器报告，不在此列举。
- `data-layer` 页内唯一；富文本只认 `span.hl` / `span.hl-line` / `br` / `strong`。
- 禁区与补空页同一套（`position:fixed` / `@media` / `@import` / `@font-face` / `url(` / 脚本与动画标签 / `animation:` / `transition:`），清单与理由见 `IMPROVISATION.md`「四条硬约束」第 3 条；内联 `style=` 两类都禁，本页样式写进页内 `<style>` 块。
- 每页有且只有一个主标题并带 `data-role`，这是字号对位的抓手；不标则无从判断该用哪一档。
- 系统槽主标题节点必须带 `data-layer` + `data-editable="text"`，否则编辑器认不到图层或认到却改不了字。

## 4. 排版三约束

### 4.1 填充：让容器吸收剩余空间

版面的头尾固定，自由度与风险都在 `.content`。骨架天然分为"顶对齐纵列 / 居中 / 网格均分"三类，只有顶对齐纵列需要显式声明填充；居中骨架写填充反而破坏居中，网格骨架的填充声明是空操作。各骨架的分类与可用写法由校验器判定，违反时报错会指名。

判据是**让装内容的容器吸收剩余空间**，不是新增空节点去顶页脚——空壳能把后面的元素推到底，却买不到版面。填充机制只解决"谁吃掉剩余空间"，不解决"版面是否空"，后者由密度约束管。

顶对齐纵列必须显式声明填充，三种写法任选其一：共享类 `.fill-grow` / `.fill-sink`、页内 CSS 直接写 `margin-top:auto`、或让 `.content` 的直系子元素自己 `flex:1`（推荐：容器吸收，不新增空节点）。空着不放内容的空壳会被点名——它不算有效填充。

`data-fill="grow|sink"` 标记**已停用**：它既不产生布局效果，也难校验，写了只会让人误以为已声明填充。改用上面三种。

### 4.2 密度：默认要满，留白要申报

文本跨高、实际覆盖率、尾白、字间空隙由几何体检在截图会话里实测（真实文本位置，静态规则查不了）。**三个判据任一命中即欠填**：实际覆盖率 < 40%（内容真正占了多少高度，主判据）、文本跨高 < 70%（首末内容是否撑到两端）、尾白 > 18%（底部是否空着）。只看跨高会被「首尾各放一个元素、中间全空」骗过——所以以覆盖率为主。

图片与内嵌图形算版面内容，和文本一起计入——「小标题 + 大图」的页不会被判欠填。绝对定位是正常排版手段，用它摆的图和卡片照样算内容；只有**画面上什么都没有的空 `<svg>`**（无图形子节点）不计——空骨架撑出来的面积不是内容。装饰性小图标（面积不足 `.content` 的 6%）也不计：否则在页底放一枚 2.4cqw 的图标，就能把尾白压成 0、把跨高拉满，真正的半页空白被静默放过。

刻意留白的页（封面金句、收尾大字）在根节点写 `data-density="airy"` 申报——不申报的空是漏排，申报的留白是设计。

内容偏少时按此优先级修，别只会调 CSS：

1. **换结构**：用横向容器（宽而扁），不要用竖长框。两条内容塞进高竖栏，怎么对齐都会空；改横卡立刻填满。
2. **升字档**：正文与条目标题升一档，内容体积实打实变大。
3. **补次级信息**：加真正有用的附属内容（索引、适用场景、例子），不是灌水凑高。

`margin-top:auto` 只是把空白从块外搬进块内，不解决欠填。内容实在不够就拆页、减页，或申报极简。

### 4.3 禁止重叠与散乱

- 文本块之间不得显著互相压盖：调间距（走令牌）或改布局结构，不要靠叠放碰运气。
- 标题断行手动安排，末行不留孤字；中文引用类内容避开非等宽列骨架（会把长句挤成孤字）。正文末行单字在中文排版里常见，只提示人审，不硬拦。
- 分割线类元素在居中容器里会塌成点，改空隙或自带边界的卡片，别靠它撑结构。

## 5. 组件与视觉值

组件三个来源，都合法：

1. 本风格 `components.md` 登记的共享类，直接用。
2. **复制现有母版组件的结构**：把 markup 复制过来当骨架，专属类名改成自造名，视觉做法在页内 `<style>` 用自己的选择器重写。母版的版式结构与组件语汇是允许复用的素材；禁止的只是原样引用一个本页拿不到 CSS 定义的类名。
3. **完全自造组件**：从零设计结构与样式，类名在页内 `<style>` 有定义即可。

不自造视觉值：字号、间距、行高、字距、圆角、深底只用本风格 `:root` 已登记的令牌档；强调色与字体栈不开放。页内可写 `<style>` 块放自造组件样式（覆盖顺序在全局 CSS 之后，每页独立不互相污染），其中每个视觉声明都须令牌化，布局属性自由。内联样式、裸值、自造变量一律硬拦。

大标题用衬线；标题/金句的高亮用 `span.hl-line`，正文小强调用 `span.hl`。块自带边界时用空隙分隔，裸文本块才用线——线是"替代边界"，不是装饰。

**为什么不打通所有母版的类名**：母版专属类的数量、跨母版重名情况由 `catalog.md` 与样式表决定，全改通用类名是高风险零收益的重构。"复制结构 + 改自造名"用页面级 CSS 就解决了，不需要动母版体系。

## 6. 图与字数

- 图按相对任务工作区路径写 `<img src="shots/a.png">`，出图时自动转 base64（不产 `assets/`，交付 HTML 自包含）。图槽写法与必填规则见 `components.md`，图槽没有"可省"机制——写了就必须给值，不要无图形态就别写 img 节点。**路径本身在静态阶段就查**：缺 src / 空 src / 越界 / 文件不存在 / 扩展名与内容不符 / 外链 / `srcset` 都会在 `composed.mjs` 单跑时直接报错，不用等出图。`crop` 描述只属于母版槽位，组合页用页内 CSS 的 `object-fit:cover` 自己控裁切。
- 没有字数说明头可依：字数靠几何体检 + 目检收口，机器无精确上限可比对，别指望越档告警兜底。

## 7. 校验与自检

出图时校验随渲染自动跑；调规则可单跑静态部分：

```sh
node script/composed.mjs <任务工作区>/plan.json
node script/render.mjs <任务工作区>/ --check-geometry   # 几何与密度体检
```

静态规则、几何体检、令牌校验各自查什么，由校验器报错精确说明，不在此复述枚举。唯一没有机器规则的是字数越档，每次运行会自曝未启用。

**两个入口的分工**（静态绿 ≠ 可交付）：

| 项 | `composed.mjs` 单跑 | `render.mjs --check-geometry` |
|---|---|---|
| layoutBase / 类名 / 四件套 / 禁区 / data-role / 填充 / 令牌 / 占位符 | 查 | 查（同一份实现） |
| `<img>` 的 src 缺失、路径越界、文件不存在、扩展名与内容不符、外链、srcset | 查（路径相对 `plan.json` 所在目录） | 查 |
| 图片转 base64 内嵌、系统槽注入、编辑器图层 | 不查（不产 HTML） | 查 |
| 密度 / 压盖 / 孤字 / 主标题字号对位 | 不查（需 computedStyle） | 查 |

所以「静态 0 硬错」只说明 markup 结构合规，出图前仍必须跑一次 `--check-geometry`。

**出图后逐页自检**（机器只保证"没违规"，不保证"排得好"）：

1. 静态零硬错、系统槽无占位符残留、几何无越界。
2. 三禁逐页目检：无大段留白、无元素压盖、无标题孤字或塌陷（机器已拦其中可判定的部分，其余靠人眼）。
3. 令牌无裸值、全量字号在档内。
4. 看总览预览：底色、网格、强调色、字级跨页一致。
5. 内容事实与叙事按 `CONTENT-REFINEMENT.md` 自查——机器校验通过不等于内容对。

任一不过就修 plan 重跑。刻意留白的页确认已申报。

## 8. 转正

同一形态在多页或跨任务反复出现、或同一页改两版仍不满意时，主动提出转正为母版：按 `IMPROVISATION.md` 的转正流程入库，再做目检与真实任务回归。交付页跨任务不可重建（plan 不进交付白名单），转正是唯一复用出口。

## 9. 与即兴补空的区别

| | 即兴补空 | 自由组合 |
|---|---|---|
| 触发 | 母版能套、只是槽位撑不满，且必须保留其私有结构 | 槽位装不下或无匹配母版 |
| `layout` | `custom/<名>` | `custom/composed-<语义名>` |
| `layoutBase` | 不填 | 必填 |
| 骨架 | 抄母版整页 | 四件套自拼，借母版的 `.content` 骨架 |
| 组件 | 抄来的专属类可保留 | 共享类 + 复制结构（改自造名）+ 完全自造 |
| 转正 | 同类补空反复出现 | 同类版式反复出现 |

判档看字段不看实质：带 `layoutBase` 或 `composed-` 前缀的页按组合页校验，缺字段硬停；不带前缀也不给骨架的页按补空放行。这条入口机器堵不住（堵了就等于取消补空），靠规范与评审守。
