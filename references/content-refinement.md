# 内容提炼（写 plan 前的强制决策）

本文件是规则，不是建议清单。写 `plan.json` 之前必须完成下列决策；决策不落新文件，直接约束选母版与填字段。字段填写的高亮/断行/符号纪律见 `styles/content-rules.md`。

## 1. 定主张与承诺

- **核心主张 `[必须]`**：一句话，形如「[读者] 在 [场景] 下应该知道 [主张]」。判据：逐页核对主文案能否回溯到这句话；回溯不到的页换内容或删，不为凑数硬填。
- **观看者承诺 `[必须]`**：一句话，读者刷完这组图能获得什么。判据：封面钩子必须兑现这条承诺；正文无对应页就改封面或补内容，不留空头承诺。

## 2. 定要点与每页主角

- **段落地图 `[必须]`**：4-8 个要点，即素材能拆出的信息块。每点必须回答「它为核心主张贡献了什么」，答不上来的删除。
- **每页主角 `[必须]`**：每页先声明主角（画面 / 数据 / 步骤 / 对比 / 主张 / 金句，只选一个），再定版式。
  - 真实任务：拿主角去 `catalog.md` 比对语义组选母版；禁止按页码顺延选，禁止「素材有什么塞什么」。
  - 全母版目检：母版已由枚举先定，反向为每页定主角并配内容；主角与母版形态冲突时换内容、不换母版。
  - 判据：一页只留一个超大字块；出现两个同等重量大字块 = 没主角，降级其一。
- **页面角色 `[建议]`**：用钩子封面、问题场景、误区 vs 现实、清单、对比、截图证据、一句大引语、分步流程、总结页等不同角色承载要点，别每页都是同一种卡片。

## 3. 写钩子与文案

- **钩子 `[必须]`**：从要点里挑最该先说的写成一句，简短具体；一张封面只放一个观点，禁抽象标签与无具体对象的炒作。
- **文案 `[必须]`**：标题用「动词 + 后果」（"高帮鞋会让脚更闷"优于"鞋子选择"）；先讲用户可感知的变化，再补术语/功能名。AI/工具类先讲工作流改变（采集更快、手动更少、跨应用自动化），资讯/评测类封面用钩子文案而非平铺标题。
- **文案量 `[必须]`**：图片组是视觉提纲，只放解释画面所需的文字，详情留给帖子正文，不把整篇文章搬上卡片。
- **面向读者 `[必须]`**：文案写真实场景，不写制作术语——母版名、槽位、字数预算等内部术语不得进 H1/钩子/正文主文案。渲染前以真实观众身份通读每个可见标题，读起来像任务要求的就换成场景化文案。

## 4. 素材与品牌来源

- **事实 `[必须]`**：数字、价格、承诺、数据必须有素材出处，查不到就不写；换算要留原值、单位、口径；改写的观点不能冒充逐字引语。
- **品牌三值（`meta.brand`）`[必须]`**：来自本次真实主体（用户或文案给出的品牌/署名）。无真实主体（纯版式测试/目检/压测）时，自拟一组**明确区别于母版默认值**的测试值（如 `T` / `测试品牌` / `test.example.com`），让 sys 槽注入链路真的被验证。**严禁照抄模板示例或母版内置默认**（如 tech-blue 的 `Feiwan AI Lab` / `Feiwan · AI Lab`）——照抄等于注入没发生，整篇显示成母版品牌。

## 5. 写完 plan 的自检

逐条过，任一不过就回炉：

- 核心主张一句话说得清吗？每页都在推进它吗，还是同一卖点换句式？
- 观看者承诺兑现了吗？封面钩子具体、只一个观点吗？
- 每页只立一个主角吗？主角配了能承载它的母版吗？
- 页面角色多样吗，还是重复同一种卡片？
- 每个事实有证据吗？数字、引语、截图与解释对应吗？删减丢没丢关键口径？
- 读者不看原文能懂短句吗？长标题断行落在语义停顿了吗？
- 有无为凑页数/密度的弱主角或虚假内容？能合页就合页吗？

机器校验通过 ≠ 事实或叙事正确；内容判断由 AI 负责，以上判据逐条自查。
