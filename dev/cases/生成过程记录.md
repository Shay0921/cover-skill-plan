## 4. 第一次生成 + 第一次渲染（翻车）

跑 `node gen.js` → 26 张卡片生成成功。

**找 Chrome**：`/c/Program Files (x86)/Google/Chrome/Application/chrome.exe` 存在。

**第一次渲染失败**：用 `file://$PWD/cards/P05-A.html`（Git Bash 的 `$PWD` 是 `/c/Users/...` 前向斜杠路径）传给 Chrome，报错：
```
Page load failed: net::ERR_FILE_NOT_FOUND
```
Chrome 在 Windows 下不认这种 Git Bash 前向斜杠 `file://` 路径。

**修复**：用 `cygpath -w` 把路径转成 Windows 反斜杠格式，Chrome 直接吃 `C:\...` 绝对路径（不挂 `file://` 也行）。之后所有渲染都用这个写法：
```bash
"$CHROME" --headless=new --no-sandbox ... --screenshot="$(cygpath -w "$OUT/x.png")" "$(cygpath -w "$PWD/cards/x.html")"
```

渲染了 9 张关键卡片（P05-A/P07-A/P08-A/P11-A/P03-A/P02-A/P01-A/P09-B/P12-A）查看。

## 11. 关键决策与教训（复盘）

1. **手机壳裂图（上一轮已修）**：b64 解码前没剥离 `data:image/png;base64,` 前缀会生成损坏 PNG。本次确认手机壳已完整显示，没再出问题。
2. **"2 行标题挤占正文高度"是本次最高频的溢出根因**。规律：标题换行 → 正文高度从 ~1049px 掉到 ~891px → 手机 `maxW>34` 就会底部被裁。后续凡 2 行标题的带手机卡片，手机一律 ≤34cqw。
3. **手机屏内截图被壳裁切是预期行为**，不是设备裁切。核对时要把两者区分开，别误改。
4. **Git Bash 的 `$PWD` 前向斜杠 `file://` 路径 Chrome 不认**，必须用 `cygpath -w` 转 Windows 绝对路径。这是渲染环节卡住的关键坑。
5. **视觉模型会误报裁切**，对"被报裁切"的卡片一律二次精确复看，避免改没问题的卡片。
6. **CSS 通过 `<link>` 在渲染时读取**，改 CSS 不必重跑生成器，直接重渲染即可——省一轮 `node gen.js`。
7. **这是设计预览，不是正式出图**：系统衬线兜底、未跑 skill 的 gate 流水线（pool/plan/src 三件齐备 + 几何/越界校验）。真要发文得走 skill 原生 gate 流程。
