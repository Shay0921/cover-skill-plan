## 0. 一张标准母版的解剖（五项必备 + 两项按需）

> 本节说的是**一张母版的组成项**，与「风格目录有哪几个文件」（手册「目录结构」一节）是两回事，不要混用数量词。

一份合格母版 = 下表 7 项组成；其中 #5/#6 按母版形态决定写不写，其余五项缺一即不可实例化：

| # | 组成 | 位置 | 作用 |
|---|---|---|---|
| 1 | **说明头** | section 前的 HTML 注释 | 人读 + AI 读的总说明（§4 必填字段） |
| 2 | **section 壳** | `<section data-layout="<id>">` | 风格内唯一 id，plan.json 的 `layout` 与 render 抽 section 的锚（编辑器不读它，靠 manifest 的 `root` 定位） |
| 3 | **画布根** | `<div class="artwork-page" data-artwork data-size="1080x1440">` | 一母版一页一画布根；尺寸写死在根上 |
| 4 | **槽位系统** | 元素上的 data-* 标记（data-layer / data-label / …）+ 占位符 | AI 填内容的唯一接口（§2） |
| 5 | **repeat 槽**（按需） | 单元旁的 repeat 注释 | 弹性条目的唯一配置点（§3） |
| 6 | **装饰层**（按需） | 手机框槽 / 底纹 / 图标位 | 不进图层面板的部分：**不标 `data-layer`**（硬规则见 §2.2 第 6 条） |
| 7 | **登记同步** | 内容：catalog.md ↔ 说明头；视觉：design-system.md ↔ style.css ↔ 画廊看板 | 内容同源两处、视觉同源三处，各自改一处其余跟改；入库动作另按 §8「四登记」执行 |

外加**两份样式/资产义务**：样式进 style.css（双段制，§5）；运行资源（手机框 PNG 等）按 §6 单源内嵌，母版本体不内嵌框图。

> **按需项**：#5 repeat 槽、#6 装饰层按母版形态决定——无重复条目、无装饰资源的母版不写（§9 的最小示例即此类形态）。
> **画布根类名**：固定 `.artwork-page`（全风格通用机器锚点，权威定义在 SKILL.md「plan.json 格式」；render.mjs 的 `rootOf()` / `editor.manifest.json` 的 `root` / Chrome 截图 selector 都认它）；新风格必须沿用，不得自造根类名。

## 1. HTML 规范

### 1.1 结构骨架（直接抄此骨架起步）

```html
<!-- ============ N<序号>-<语义名> · <中文标题> ============
     用途：…（一句话）
     适合：…；不适合：…；可以变：…
     槽位：<完整 data-layer id 清单>（repeat 单元写条目短名）
     限制：<槽位 id>≤N字；<槽位 id>≤N字符；两个槽同行用空格分隔
     hl：<槽位 id> 内 0-1 处
     图槽：<比例> cover ×<张数>，竖图裁切
     来源：<出处>
-->
<section data-layout="N<序号>-<语义名>">
  <div class="artwork-page" data-artwork data-size="1080x1440">
    <!-- 画布内容：全部收在此根内 -->
  </div>
</section>
```

> **限制行的键必须 ASCII 且等于槽位 id**：`标题≤N字` 这种中文键 render 认不出来，会**静默失效**（不报错、也不校验）。括号里的内容同样不参与校验——要机器管行数就写无括号的 `<键>≤M行每行≤N字`，详细口径见 final/01「就地限制」节。

### 1.2 结构规则

- 一 section = 一页 = 一个画布根；**section 内禁止 `<style>`**（样式全进 style.css）。
- **templates.html 是母版仓库（源）**：顶部含画廊三合一头部（语义组导航锚点 + 风格看板：色板/字体/字号层级/画布规格），与 style.css 同源——改 CSS 三处一起改（style.css / templates.html 看板 / design-system.md；同步靠入库纪律，v1 无自动校验）。交付产物是 render 拆出的独立 `P<nn>-<名>.html`，templates.html 永远不进交付区。
- **画廊 chrome 豁免**：templates.html 的导航/看板/锚点脚本（section 之外的仓库层设施）允许自带 `<style>`/`<script>`——只服务画廊浏览，render 拆页只取 section 内容，不会进交付 P 页。**section 内仍严格禁止**。
- 画布固定 1080×1440；根节点带 `container-type:size`（使用 cqw 时必需）。
- 全部内容收在画布根内，不依赖外层 section / body 的 padding 定位。
- 标签白名单：常规结构标签（div/section/header/main/footer/ul/ol/li/p/h1-h6/span/img/figure/figcaption/pre/code/table 等）；**禁** form/iframe/object/embed/audio/video/canvas 动态用法；`<template>` 内不放任何正文与标记（构建期整树跳过）。
- **产物禁 `<script>`**、无动画/过渡/轮播/滚动、无外部 `<link>`、无 `<img src>` 外链（pageApp 构建期拒绝）。

### 1.3 占位符与富文本

- **命名分两层，不要混为一谈**（全库统一契约，与风格无关）：
  - **顶层文字槽 / 图槽**：`{{槽名}}` = `data-layer` id = plan.json 的 fields 键，三处同名是硬规则（`data-label` 是图层面板中文名，不参与键名）。§9 的最小示例全部是顶层槽。
  - **repeat 单元内部**：占位符用**条目短名**（`{{n}}`/`{{t}}`/`{{d}}`…），= plan 数组元素的键，*不等于*单元元素的 `data-layer` id。这是层级命名空间，不是违规——clone 时 render 会给 data-layer 加 `-2/-3` 后缀保持唯一（§3.2）。
- **`data-slot` 禁用于文字元素**（pageApp 契约：data-slot="image" 仅落 `<img>`）；图槽的 plan 键 = 图槽的 data-layer id。
- **契约是风格无关的**：换风格只换 `templates.html / style.css / catalog.md / design-system.md` 四个视觉资产，槽位命名规则由 `script/render.mjs` 单源决定，**任何风格都不得自定一套命名规范**（否则 render 要按风格分支，归一即破）。
- 富文本位允许的运行时注入标签仅：`<span class="hl">`（高亮，css 自定义颜色）、`<br>`、`<strong>`；AI 的 plan.json 字段值只能含这三类标签。**正文里的裸 `<` `>` 不是标签**（`5>3 倍提升`、`A < B`、`x<y 时`），render 注入前统一转义为实体，母版无需为它们预留任何结构；判定只看**完整标签形态**（`<b>` / `<div class="x">` / `</div>`），标签名后是中文或数字不算标签。
- 正文不得放 `::before/::after` 的 content（编辑器改不到）。

## 2. 槽位与 data-* 规范（以编辑器契约为准；本规范的扩展逐条显式标注）

### 2.1 属性表（契约 8 条 + 本库扩展 2 条）

> **取值域的唯一来源**是 pageApp《HTML产物交接规范》v1.9「属性表」一节——Windows `D:\AI\pageApp\HTML产物交接规范.md`／macOS `/Users/shay/Code/AI/pageApp/HTML产物交接规范.md`。契约明文规定「其它文档只链接到这里」，所以本表只补**本库怎么写 + 忘写会怎样**两列，取值有歧义时以契约为准。
> **编辑器实装锚点**：`pageApp/demo`（2026-11-01 开发版；v1.9 只校准表述、未改代码）。扫描入口 `demo/lib/markers.mjs` 实际读 **6 条**——`data-layer`/`data-label`/`data-type`/`data-editable`/`data-group`/`data-slot`；`data-artwork`/`data-size` 未读（契约对照表已写明）。扩展属性与契约怎么同步，见「扩展属性与契约的同步关系」节。

| 属性 | 值 | 放在哪 | 本库怎么写 / 忘写后果 |
|---|---|---|---|
| `data-artwork` | 无值 | 画布根 | 每张母版必写。契约截至 v1.9 尚未读取（编辑器靠 manifest 的 `root` 找根），写上是为了根节点自描述、换 skill 时不必再问「哪个是画布」；render 对即兴页（`custom/*`）的形态校验会**强制要求**它 |
| `data-size` | `1080x1440` | 画布根 | 每张母版必写。契约截至 v1.9 尚未读取（编辑器固定 1080×1440），作用同上；即兴页缺它直接报错 |
| `data-layer` | 全页唯一 kebab-case 英文 id | 要成为图层的元素 | 忘写 = 不进图层面板；重复 = 构建期报错 |
| `data-label` | 中文短名 | 同 `data-layer` | 忘写 = 面板直接显示 id 本身（实测回落 `label || id`，不报错，只是人读着费劲） |
| `data-type` | `text` / `group` / `image` | 同 `data-layer`（可省，自动推断） | 忘写可推断（`<img>`→image、有块级子元素→group、否则看有无文字）；类型只决定拖拽/缩放粒度，**改字靠叶子自己的 `data-layer` + `data-editable`，与本列无关** |
| `data-editable` | `text`（不能写空值或别的词） | 包住文字的叶子元素 | 忘写也能改字（无块级子元素的叶子会被推断成 text）；写上是为了**显式锁住「可改文字的叶子」**，免得日后结构调整（塞进块级子元素）被推断成 group。取值写错即报错 |
| `data-group` | **无值** | 组合容器 | 忘写 = 只含行内元素（`span` 等）的容器会被推断成 **text**，编辑时按「整块改字」处理而不是移动/缩放 → 这类容器必须显式写 |
| `data-slot` | `image` | **仅 `<img>`** | 忘写 = render 不认它是图槽（不换 src、不补 `data-filled`），plan 里那张图的键随即报「与母版槽位对不上」；编辑器虽能按 `<img>` 推断成 image 类型，但两条链路口径已经分叉 → **必写** |

> **本库扩展（契约 8 条之外只有这两条；编辑器都不读，只增不改是安全的）**：
> - `data-ratio`（如 `4:3`／`212:291`，图槽 img 或容器任写其一）——render 读它做「图片与槽位比例」软校验（**只判 PNG 尺寸头**，JPEG/WebP 不判）。
> - `data-fit`（`cover` 默认 / `contain`）——写在图槽容器上，**CSS** 读它决定 `object-fit`。
>
> 另有 `data-filled`（render 填图后补在容器上，母版**禁手写**）与 `data-repeat`（repeat 锚点，见「repeat 槽规范」），二者都不是交付方手写的契约属性。写法见「图槽结构」节，同步判定见下一节。

### 2.2 硬规则（违反 = 构建期报错或图层失效）

1. `data-layer` 全页唯一；只许字母数字-连字符-下划线；禁中文、空格、`#`、`.`、首尾空白。
2. **容器标 group、文字标叶子**——只标容器不标叶子 = 卡片内文字全部改不了（最常见的错）。
3. `data-slot="image"` 只能落 `<img>`；`text` 类型不能落 `<img>`；同一元素类型标记互斥。
4. 根节点不加 `data-layer`；标记不进 `<template>`。
5. 高亮 `<span class="hl">` 与 `<br>` 编辑安全，可放心用。
6. 装饰性元素（底纹/图标/页码/手机框）**不标 data-layer**（减少图层面板噪音）。
7. `data-label` 按 HTML 规则解码实体：要显示 `&`、`"`、`<` 就写 `&amp;`、`&quot;`、`&lt;`，不要写裸 `<`（契约「属性表」一节同款要求）。

### 2.3 图槽结构（图片只有一条替换通道）

```html
<div class="img-card ph-img" data-fit="cover">        <!-- 容器：cover 默认 / contain 完整显示 -->
  <img class="ph-img__img" data-slot="image" data-layer="n10-img-1" data-label="图 01"
       data-ratio="212:291" src="data:image/png;base64,iVBORw0KGgo…（1×1 占位 PNG）" alt="">
  <span class="ph-img__label">IMG · 1280 × 720</span>  <!-- 占位标签：母版期可见，填图后隐藏 -->
</div>
```

- 图槽 = **容器 + 唯一实图层**：容器带 `.ph-img` 与 `data-fit`（`cover` 默认，按比例裁切填满 / `contain` 完整显示），内含**唯一** `<img data-slot="image">`，占位标签与 img 同级、**必须带 `.ph-img__label` 钩子**（CSS 靠它隐藏标签；前缀 `placeholder` / `ph` 是历史写法，不参与命中）。
- **render 与编辑器都只替换这个 img 的 src**（dataURL），`data-slot / data-layer / data-label / data-ratio` 原样保留——漏写会让 render 认不出图槽（plan 图键报「与母版槽位对不上」），crop 时外包一层裁切容器。其中 `data-ratio` 与容器上的 `data-fit` 是本规范扩展（见「属性表」节末）；`data-fit` 在编辑器里会被它自己的「适配方式」覆盖，见「扩展属性与契约的同步关系」节。
- 占位必须是 **1×1 占位 PNG**（白色、可拉伸填满槽位），不能用 GIF：契约只放行 PNG/JPEG/WebP，GIF dataURL 会让 `pack.mjs` 直接失败（见「图片与资产规范」）。
- 填图后由 render 给容器补 `data-filled`，CSS 据此隐藏占位标签——**母版里不要手写 `data-filled`**。
- 容器上**不写** `data-img`，CSS 里**不写** `--img` 变量：图片只有「替换 `<img>` 的 src」这一条通道。

> **未激活风格的例外**：paper-journal `masters/` 41 档仍是旧形态（`src="{{图}}"` 占位、无 `data-ratio`/`data-fit`、另带 `data-from`），T4 激活时按本节统一——它们不在生产路径内，不构成规范的例外条款。

### 2.4 扩展属性与契约的同步关系（什么时候需要动 pageApp）

判定只有一句：**编辑器要不要读它做事？** 要 → 进 pageApp 契约（v1.x 升版，本库改引）；不要 → 只留在本规范的扩展清单，并写明「编辑器不认」。

| 档 | 属性 | 谁在读 | 编辑器要不要跟 |
|---|---|---|---|
| 契约属性 | 8 条 | 构建期扫描（读 6 条）+ render 的 custom 页根校验 | 已对上，母版增到多少张都不用改编辑器 |
| 本库扩展 | `data-ratio` / `data-fit` | render / CSS | `data-ratio` 不用；`data-fit` 有边界，见下 |
| 产物标记 | `data-filled` / `data-repeat` | render 自己读写 | 永不进契约 |

- **实测依据（为什么「只增不改」安全）**：编辑器扫描不校验未知属性（给容器多写 `data-fit`/`data-ratio`/`data-filled` 不报错、也不会误判成图层）；导出走 `clone.innerHTML` 全量序列化，只删自己写的 `data-ed-*`，扩展属性能原样往返。
- **新增母版不会拖累编辑器**：图层契约是「每个元素标什么」，与母版张数无关。新母版沿用 `.artwork-page` + 8 条属性，编辑器靠 manifest 的 `root` + `layerMode: markers` 直接接上（本机实测：8 页 11 个图槽全部扫成 `type:image` 图层、整页 159 个图层，`pack.mjs` 0 warning）。真正会逼 pageApp 改代码的只有三处——**根类名**、**manifest 字段**、**属性取值域**（`text/group/image`、`data-group` 无值、`data-slot="image"`）。
- **唯一有边界的扩展是 `data-fit`**：编辑器把「适配方式」存成自己的图层状态（`defaults()` 写死 `cover`），`mount()` 里对每个图层跑一次 `applyLayer()`，给 `<img>` 写内联 `object-fit`；内联优先级高于 CSS 属性选择器，所以**打开页面即覆盖母版的 `data-fit`**（真编辑器实测：同一槽裸读 `contain`，打开后 `computed` 变 `cover`）。
  但**后果取决于「图与槽是否同比例」**，不是无条件裁切：当前全库唯一 `contain` 槽是 N29 二维码（86×86，1:1），二维码本身也是 1:1 → `cover` 与 `contain` 渲染结果完全相同、**零损失**（实测两批交付页均未用到该槽，现实中尚未发生）。只有往 contain 槽塞**非等比图**才有差别：实测 4:3 图进 1:1 槽，`cover` 渲染宽 115.2px 被槽裁到 86px，**横向损失 25%**，二维码四边被切就可能扫不出。
  因此当下不需要任何补救动作，规则收敛成一句：**contain 槽只放与槽同比例（1:1）的图**。要根治再向 pageApp 提「读容器 `data-fit` 作为适配方式初始值」（v1.10 候选，TODO T7）。
- **契约升版时的复核动作**：读契约「契约对照表」，看是否有属性从「未读」变「已读」；某个扩展被收编（例如 `data-fit` 变已读）就把它从本节移进「属性表」并改口径；再跑一次 `node pack.mjs <运行区>`，确认 0 warning。

## 3. repeat 槽规范（条目弹性的唯一配置点）

### 3.1 语法（全库唯一语法定义处 = 本节；数值只写在母版注释里）

```html
<!-- repeat ×<min>-<max>: <克隆规则一句>；<条数-字数联动一句> -->
<div class="item" data-repeat="items">
  <div class="num" data-layer="item-num" data-editable="text">{{num}}</div>
  <div><p class="t" data-layer="item-t" data-editable="text">{{t}}</p>
       <p class="d" data-layer="item-d" data-editable="text">{{d}}</p></div>
</div>
```

> 单元元素必须带 **`data-repeat="<数组键名>"`**（plan.json 数组字段的键，机器锚点）；注释承载区间与联动（机器解析的另一半）。单元内占位符用**条目短名**（{{num}}/{{t}}/{{d}}，= plan 数组元素的键）。

### 3.2 规则

1. 任何重复型组件适用（清单/待办/卡片/行/通知/图卡…）；一个母版可有多处 repeat 槽，各管各的。
2. 机器配置值（区间 ×min-max、每槽 `≤N字` 精确限值）**只配置在母版注释里**；catalog 可写选型判断用的量级语义（如「适合 3-8 条」「标题两行内」），两种数字含义不同、不构成重复配置。
3. 布局必须用 flex/grid 弹性实现（`flex:1` 均分等），保证区间两端都不溢出、不空塌。
4. plan.json 传数组 → render 克隆并**校验区间**（超出 ×min-×max 即停）；AI 不手工复制节点。
5. 克隆单元内的 data-layer id 由 render 加序号后缀（item-t-2、item-t-3…），母版只写第一份。

## 4. 说明头规范（必填字段清单）

每个 section 前的注释块必须含全部字段，缺一即未入库（下例摘自 N10 实况，字段一行不少）：

```html
<!-- ============ N10 · 工具清单 v2 ============
     用途：工具/资源推荐——左编号清单 + 右 2×3 图格
     适合：3-8 条量级推荐 + 有截图素材；不适合：每条需长说明（d 一行）
     可以变：条目 3-8 条（行距自适应）；右栏图格固定 6 格，可 L2 减格
     槽位：big-num / tag / title / sub / items[]（num,t,d）/ 图×6（212:291 cover）/ page-no
     限制：big-num≤2字符且=条数；title≤16字(2行,每行≤8字)；sub≤16字(1行)；t≤12字；d≤16字(1行)
     hl：title 内 0-1 处
     图槽：竖版 212:291 cover ×6
     来源：ai-covers N10
-->
```

- 「图槽」行只在含图槽时写，比例要与图槽的 `data-ratio` 一致（两处不一致时以母版属性为准，人审时核对）。
- 「限制」行是 render 字数软校验的解析对象——**写实测值**（该字号下不折行不溢出），不写感觉值。
- **键必须是 ASCII 且能被软校验命中**：render 解析 `键≤N字`（视觉宽度）/ `键≤N字符`（码点数）/ `键≤A行每行≤M字|字符`（行数 + 单行）；键支持同名、族名（`th`→th1..th4）、区间（`c1..c3`）、尾随 `*` 通配（如 `sm*-label`），再与展开后的字段集（顶层槽键 + repeat 条目短名，克隆体带 `-2/-3` 后缀）比对。**顶层槽写完整 `data-layer` id，repeat 单元写条目短名**。中文键（`标题≤10字`）与括号里的数值（`(2行)`、`(2行,每行≤7字)`）**都不解析、静默不校验**——要机器管就写无括号的 `≤2行每行≤7字`。宽度权重、行数写法与容差口径见 final/01「就地限制」节。
- 说明头与 catalog.md 条目**同源同步**：改一处另一处跟改。

## 5. CSS 规范（双段制）

### 5.1 归属判定（唯一问题）

> 「这个类会不会被第二个母版复用？」 —— 会/可能 → **共享段**；不会 → **专属段 + 母版前缀**（如 `.n10-tool-list .item` 或 `.n10-item`）。

```css
/* ===== 共享段：全风格母版公用的组件类 / 基础类 ===== */
/* ===== 专属段：仅个别母版使用的类，集中放尾部，类名强制母版前缀（如 .n01-shock）===== */
```

### 5.2 纪律

| 项 | 规则 |
|---|---|
| 文件位置 | 全部样式进 `styles/<风格>/style.css`；section 内禁止 `<style>` |
| 令牌优先 | 颜色/字号/间距一律用 `var(--token)`（tokens 在 style.css 顶部 :root 或 style-guide 定义）；新令牌 = 风格演进 = 用户过目 |
| 单位 | px 或 cqw（cqw 需根节点 `container-type:size`；各 section 根自带 container-type，同页多容器互不干扰）；**禁** vh/vw |
| 选择器 | 扁平（≤2 层）；禁 CSS 嵌套语法（编辑器未验证） |
| 禁区 | `position:fixed`、窗口断点 `@media`、动画/过渡/滚动 |
| 弹性设计 | 重复区必须弹性（flex/grid 均分），条数变化自动伸缩；关键区域预留行数余量；不依赖 nowrap 保布局 |
| 命名 | 类名小写连字符；组件类用语义名（card/row/badge/tag）；专属类必须带母版前缀 |

## 6. 图片与资产规范

- 图槽必须声明 `data-ratio`（或由 css aspect-ratio 定死）；素材与槽位比例不符 → `object-fit:cover` 居中裁切。裁切选区（杂乱图的 `crop`）由 plan 侧给，见 final/01「图片决策表」。
- 手机壳母版：截图槽 + `frame-img` 装饰槽（不标 layer）；**框图由 render 单源内嵌**（读 styles/assets/iphone-frame.png 现场编码，缺文件即停；画廊以 ../assets/iphone-frame.png 直接引用），母版里不内嵌框图数据。
- 允许格式 PNG/JPEG/WebP；SVG/GIF/AVIF 禁（pageApp 构建期拒绝）。**占位图同样受此约束**：母版里那 1×1 占位必须是 PNG dataURL——GIF 版本（`R0lGOD…`）只要残留到交付页，`pack.mjs` 就直接抛「内嵌图片类型不受支持：image/gif」（本机实测），整批打包失败。
- 跨风格共享装饰件放 styles/assets/（如手机框 iphone-frame.png，render 内嵌 + 画廊以 ../assets/ 引用）；风格 assets/ 只装本风格独有装饰资源（可为空/不存在）；示例截图不进库（画廊显示 ph-img 占位态）。

## 7. 字体规范

- 默认策略 = **本机字体栈**：`--serif/--sans/--mono` 直接声明本机字体族（如 `"Noto Serif SC","Songti SC",serif`），母版不引 CDN、不加载 webfont、不做 base64 内嵌。
- 理由：编辑器导出 PNG 只认本机已装字体与 base64 内嵌（pageApp「资源」一节）；走本机栈可保证画廊、交付页、编辑器导出三处字形一致，且离线可用。
- `styles/assets/fonts/` 的 fontsource 分片当前未接入；日后确需 webfont，作为可选增强单独立项（须同时解决交付页内嵌与字重对应），不在当前默认路径内。
- 本机实测命中哪些 face、换机后怎么复核（`--font-report`）、字数限值为何随字体失效，见 final/01「字体策略」。

## 8. 创建工作流（七步 · 新母版从 0 到入库）

1. **定位**：读 design-system.md + catalog.md，确认语义空缺（哪个组缺哪类内容）、写好四栏草案。
2. **起草**：复制同风格最相近的既有母版（或本文件 §9 骨架）到新 section，改版式结构与类名（专属类即加前缀）。
3. **上样式**：共享段优先收录（判定见 §5.1），真专属进专属段；禁局部 `<style>`。
4. **打标记 + 占位符 + 限制注释**：按 §2/§3/§4 逐项完成；槽名三处同名（{{槽名}} = data-layer id = plan 键）。
5. **假文字自检**：最长文案（取限制上限）不溢出、最短不空塌；repeat 槽取区间两端各试一次；暗色（若有）再试一遍。
6. **机器校验**：render 出单页（或 pageApp 打包器试跑）——三层校验全过、图层面板检查（每个要改的字都在）。
7. **入库四登记**：templates.html（含画廊导航锚点）+ catalog.md 条目 + design-system.md 组件语义 + style-picker.md（仅新风格时）；用户目检通过即正式。

**二次开发（改既有母版）的三层边界**：

| 动作 | 层级 | 规则 |
|---|---|---|
| 填内容 / 改条数（区间内）/ 换图 | 任务适配 | plan.json 解决，不碰母版 |
| 改某母版的结构/槽位/限制数值 | 改母版 | 同步 catalog 条目 + 说明头（同源）；用户目检 |
| 改共享类 / 新增组件类 / 改令牌 | 风格演进 | 用户过目改 style.css + design-system.md 登记（影响全风格所有母版） |

删除母版 = 用户裁决（templates 的 section + catalog 条目 + design-system 组件语义 + 画廊导航锚点，四处一并删除）。
