> **版本**：v1.1 · 2026-11-15（新增：风格三件套、受控即兴与转正管道、图片决策表、分层校验）。本文是固定母版制架构下的唯一生产规范。

## 0. 一句话架构

**风格三件套定死视觉（CSS + 风格纪律 + 母版集），内容由 AI 填入，母版覆盖不了时 AI 可在风格词汇内受控即兴，即兴用顺了转正入库，出图由脚本完成，微调交给编辑器。**

```
文章 → AI 提炼 → 用户定风格 → 逐页选母版（或受控即兴）→ plan.json
     → node render.mjs runs/<任务>/ → out/P01-xxx.html + PNG + 编辑器契约文件
     → 人看 PNG → 交付 →（可选）编辑器微调 → 任务收尾转正盘点
```

AI 的职责 = **选**（风格/母版/槽位图）+ **填**（按槽边限制）+ **受控即兴**（仅当母版覆盖不了）。抽取、组装、截图、校验全是脚本动作。

## 1. 目录与风格库组织（每风格三件套）

```
cover-skill-plan/
  SKILL.md                 ← 驱动 AI 的入口（SOP v2）
  final/                   ← 本手册、钟摆档案、资产清单
  render/
    render.mjs             ← 出图脚本（§5）
    lib/                   ← cdp.mjs、find-chrome.mjs
  styles/
    <风格名>/
      style.css            ← ① 视觉词汇表（硬边界：即兴只准用这里的类）
      style-guide.md       ← ② 风格语义与纪律（软约束：即兴时必读）
      templates.html       ← ③ 母版集平铺（预览画廊 + 仓库）
    README.md              ← 风格选择器表（风格×适合文案类型·待建）
  runs/                    ← 任务工作区（gitignore）
```

- 规模预算：4-8 风格 × 20-40 母版 = 全库 20-30 个文件。
- **风格定稿即锁定**：改 style.css = 风格演进 = 用户过目（与改母版同级，不是随手事）。

## 2. 出图全流程（SOP v2）

1. **任务初始化**：建任务目录（交付区外 `runs/<日期-主题>/`），收集素材（文案 + 图片清单）。
2. **内容提炼**：AI 整理/提炼/升格，定页数与每页语义。**纪律：可润色不可编造**——数字与承诺必须有素材出处。
3. **风格选择（人机协作）**：AI 依内容主题 + 各风格"适用主题"说明推荐 1-2 种，用户拍板或直接点名。
4. **素材图片识别**：按 §3.6 图片决策表逐张分类定处理方式。
5. **逐页选母版 + 槽位适配**：按 `data-layout` 标签与限制注释选母版，按槽边限制适配文案（条数在 repeat 区间内取舍）。
6. **受控即兴（仅当母版覆盖不了）**：AI 读 `style-guide.md`，**只用 `style.css` 既有类**现场排版；plan.json 登记 `layout: "custom/<语义名>"`；校验自动升级（见 §6）。**禁止内联样式、自造 CSS 变量、新类名**——引入新类 = 风格演进 = 用户过目。两次即兴不满意同一内容 → 改走转正管道（§4.2），不无限即兴。
7. **写 plan.json → 跑 render** → 三层校验（§6）→ 交付（只含 `P*.html` + `*.png` + `assets/`，命名 `日期-主题/`；plan.json 留 runs/ 不进交付）。
8. **任务收尾转正盘点**：AI 扫本任务与历史任务的 `custom/<名>` 登记次数，同名 ≥2 次 → 提示用户"建议收进版式库"（§4.2）。
9. **编辑器微调（已可用）**：`cd /d/AI/pageApp/demo && node pack.mjs "<交付目录>"` → covers-edit.html。

## 3. 母版开发规范（写新母版必读）

### 3.1 结构

- 每母版 = templates.html 里一个 `<section data-layout="<风格内唯一id>">`，头部注释写用途与限制。
- 内部有且只有一个画布根：`<div class="p-page" data-artwork data-size="1080x1440">`。
- 一母版一页；产物形态是 `P01-封面.html` 这种 `P\d+` 命名的独立文件（render 负责拆分），templates.html 永远是源仓库。

### 3.2 CSS 纪律（全部进 style.css）

- 扁平选择器（CSS 嵌套在编辑器未验证）；px 或 cqw（cqw 需根节点 `container-type:size`）。
- **禁** vh/vw、`position:fixed`、窗口断点 `@media`、动画/过渡。
- 画布 1080×1440 写在根节点；尺寸固定不许改。
- 母版间布局差异用类名区分，不做内联覆盖。

### 3.3 图层标记契约（照抄 pageApp v1.9 §4.1，逐字执行）

| 属性 | 值 | 放在哪 |
|---|---|---|
| `data-layer` | 全页唯一 kebab-case 英文 id | 要成为图层的元素 |
| `data-label` | 中文短名 | 同上 |
| `data-type` | `text`/`group`/`image` | 同上（可省） |
| `data-editable` | `"text"` | 包住文字的叶子元素 |
| `data-group` | 无值 | 组合容器 |
| `data-slot` | `"image"` | 仅 `<img>` |

硬规则：容器标 group、文字标叶子（标容器不标叶子=内部文字改不了）；`data-layer` 全页唯一禁中文/空格/首尾空白；`data-slot="image"` 只落 `<img>`；根节点不加 data-layer；正文不进伪元素 content；高亮 span 与 `<br>` 安全。

### 3.4 槽位与占位符

- 文字槽：`<h1 data-layer="cover-title" data-label="主标题" data-editable="text">{{标题}}</h1>`——**占位符名与 data-layer id 一致**（plan.json 的 fields 键即它，也是编辑器 fields.json 的键）。
- 图片槽：`<img data-slot="image" data-layer="cover-image" data-ratio="4:3" src="{{图1}}">`。
- 清单槽：写**一个**完整单元 + `<!-- repeat ×3-5: 逐条复制；等高 -->`，plan.json 传数组，render 克隆。

### 3.5 就地限制（必写）

每个 section 头注释写死该母版全部填字纪律：

```html
<!-- ============ T05 清单 · 待办 ============
     用途：待办/勾选/条件核对
     限制：标题≤12字(1行)；副题≤20字；条目3-5条(标题≤14字/说明≤18字)；
           图槽 4:3 竖图会裁；hl：标题内 0-1 处 -->
```

限制注释是**机器可读的**——render 解析"≤N字"做字数软校验（§6）。写实测值：该字号下不折行不溢出。

### 3.6 图片决策表（素材四分类，AI 识别后对号入座）

| 素材类型 | 识别特征 | 处理 | 去向 |
|---|---|---|---|
| **手机截图** | 竖长（≈9:19.5）、状态栏/圆角特征 | 套手机壳槽（壳是母版的一部分，图进壳内，cover 裁切或 contain+底色）。**手机框本体由 render 自动兜底**：母版中 `frame-img` 类槽位（装饰层）若 plan.json 未指定，render 自动从 `seed/iphone-frame.b64` 解码内嵌——内容方无需提供框图 | 手机壳母版（锌灰橙 T11；纸质风 .phone） |
| **窗口截图**（浏览器/应用） | 顶栏/地址栏/标题栏特征，横版 | 图进窗口内容区槽位；**原图自带窗口边框的**用无边框槽直接放，避免双框 | 锌灰橙已有窗口组件（.chrome/.card--dialog/.ph--flat）；其他风格如缺窗口槽=新母版需求 |
| **干净内容图** | 主体明确、构图完整 | 直接用，槽位比例 cover 裁切 | 任意图槽 |
| **杂乱图**（全屏截图/聊天长图/信息密度高） | 多区域并存、主体不清 | **AI 读图选区**：在 plan.json 给该槽写 `crop` 描述（如 `"crop": "下 55%"` 或 `object-position` 值），render 用 CSS 区域显示实现裁切 | 裁剪后进任意图槽 |

图片处理总则：
- 允许格式 PNG/JPEG/WebP；GIF/SVG/AVIF 拒绝（pageApp 契约）。
- **裁切由 CSS 机械完成（object-fit / object-position / crop 区域），AI 不做像素级编辑**——AI 负责"判断"（类型/选区/槽位匹配），零漂移。
- AI 选区是"看图说话"，精度有限：**人审 PNG 是裁切质量的最终把关**；像素级精确裁剪（真改文件）登记为可选增强（需图像库，v1 不做）。
- 形状严重不符的内容换槽位或换母版，不硬塞（历史教训 p19）。

### 3.7 字体策略

编辑器导出 PNG 只认 base64 内嵌与本机已装字体；CDN/本地外链字体屏显正常、编辑器导 PNG 必然回退（pageApp §3.3 三态表）。
- 中文字体：**只用本机字体栈**（"PingFang SC","Microsoft YaHei",sans-serif）。
- 小体积西文字体（Inter 等 latin 子集几十 KB）：render 出页时 base64 内嵌。

### 3.8 禁区

产物无 `<script>`（图标 render 时内联 SVG）；无动画/轮播/滚动；无外部 `<link>`、无 `<img src>` 外链。

## 4. 语义选择、受控即兴与转正管道

### 4.1 语义选择

- 每风格 templates.html 顶部维护母版目录表（data-layout 标签 + 用途注释，AI 顺序扫描）。
- 标签按内容语义命名（"清单·待办"），不按画面特征。
- `styles/README.md` 风格选择器表（待建）：风格 × 适合的文案类型 × 反例。

### 4.2 受控即兴与转正

- **即兴的边界**：只用 style.css 既有类 + 遵循 style-guide.md 纪律；layout 登记 `custom/<语义名>`。
- **即兴页校验自动升级**：类白名单必查 + `--check-geometry` 默认开（§6）。
- **转正触发**：同名 `custom/<名>` 累计 ≥2 次 → AI 提示用户建议入库。
- **转正动作**：AI 按本章母版规范**重整**（补标记契约/占位符/限制注释/进 templates.html 顶部目录表）→ 用户目检 → 入库 → 用一个真实任务回归一次。**转正不是复制粘贴当次 HTML**。
- **风格词汇扩展**：即兴时确实需要新类 → 修改 style.css = 风格演进，须用户过目并在 style-guide.md 登记该类的使用语义。

## 5. render.mjs 规格

| 项 | 内容 |
|---|---|
| 输入 | `runs/<任务>/plan.json` + 图片素材 |
| 步骤 | 按 layout 抽 section（custom 页=AI 产出的整页 markup 直接过校验）→ 填槽/克隆 repeat/执行 crop → **frame-img 槽自动兜底手机框**（解码 `seed/iphone-frame.b64`，承接旧 build.mjs:107 的"标准名拦截"机制）→ 图标 SVG 内联 → style.css 内联 → 图片内嵌或落 assets → 包独立壳写 `P<nn>-<名>.html` → Chrome 截图 1080×1440 → 生成 `editor.manifest.json` + `fields.json` |
| 硬校验（即停） | `{{` 残留 / 图片缺失或格式不符 / 根节点与画布确认 / `data-layer` 全页唯一 / 必填槽为空 |
| 软校验（WARN） | 字数超限（解析限制注释）/ 图片与槽位比例差异大（提示裁切量） |
| 即兴页专项 | **类白名单**（class 必须在 style.css 定义）/ **`--check-geometry`**（溢出/遮挡/裁切三项几何检查，custom 页默认开——体检逻辑裁自旧 validate.mjs R1/R2/R3） |
| 地基 | render/lib/（cdp、find-chrome）；CSS 内联与资产内嵌段裁自旧 build.mjs；manifest 生成参考旧 pipeline 实现 |

## 6. 校验分层
