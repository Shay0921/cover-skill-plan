## 0. 一句话架构

**风格目录定死视觉**（构成清单权威定义在 `styles/style-picker.md`，全在 `styles/<风格>/` 内），AI 依 style-picker 定风格、读该风格 catalog 选母版、写 plan.json，render 实例化出图（HTML+PNG），母版覆盖不了时 AI 在风格词汇内受控即兴，用顺了转正入库，微调交给编辑器。**

```
文章 → AI 提炼 → 用户定风格（style-picker.md + 画廊 templates.html）→ AI 读该风格 catalog.md 选母版 → 写 plan.json
     → node script/render.mjs <任务运行区>/ --delivery=<交付目录>
     → 产物先全写任务运行区 → 三层校验与逐页截图全过 → 白名单拷贝交付目录（§6）
     → 人审 →（可选）编辑器微调
```

AI 的职责 = **选**（风格/母版/槽位图）+ **填**（plan.json 按槽位申报内容）+ **受控即兴**（仅当母版覆盖不了）。填充、截图、校验、交付全是脚本动作。**技能安装目录运行期只读**，临时脚本与过程件一律在任务运行区执行（§6）。

## 2. 生产 SOP（v2.1 · 八步）

> 全流程图（SVG·浏览器打开）：[02-SOP全流程图.html](02-SOP全流程图.html) —— 八步主线、判定分支、返修循环、受控即兴分级支线、转正管道、只读资产层的唯一权威视图，与本节同步维护。
> **同步义务（故意的双份）**：这八步在生产包里有一份自包含副本 `SKILL.md`「工作流程（八步 · v2.1）」——生产环境不带本文件，所以步骤正文必须两处一致；改步骤时同步三处：本节 / SKILL.md / 流程图。

1. **任务初始化**：在 agent 临时工作区建 `runs/<日期-主题>/` 作任务运行区（§6），收集素材（文案+图片清单）。
2. **内容提炼**：AI 整理/提炼/升格，定页数与每页语义。**纪律：可润色不可编造**——数字与承诺必须有素材出处。
3. **风格选择**：AI 依 `style-picker.md` 的名片推荐 1-2 种，用户拍板或直接点名；需要看版式时打开该风格 `templates.html` 画廊。
4. **素材盘点与识别**：按 §3.2 四分类逐张盘点（手机截图/窗口截图/干净图/杂乱图）——**只做资产属性分类，产出素材清单**（供⑤选母版与⑥匹配使用）；处理决策在⑥（此时已确定槽位与比例）。
5. **逐页选母版**：读 `styles/<风格>/catalog.md`（语义组+四栏）选定每页版式；**输入含素材类型分布（④）**——有手机截图的页才考虑手机壳母版；精确条数与字数从选中母版的 repeat 注释与说明头读取。
6. **图片×槽位匹配**：决策表落地——手机截图→手机壳槽（框自动内嵌）/ 窗口截图→窗口槽（防双框）/ 干净图→直接用 / 杂乱图→AI 读图选区 crop；裁切由 CSS 机械执行，AI 不做像素级编辑；不符→换槽/换母版。
7. **写 plan.json**：按槽位申报内容（fields 键=槽位锚：文字槽={{槽名}}=data-layer id、图槽=图槽 data-layer id；数组=repeat 条目；受控富文本 span.hl/br/strong）。**母版覆盖不了时走受控即兴**（§4.2 分级阶梯）：layout 登记 `custom/<语义名>`。
8. **render → 三层校验（硬校验 → 软告警 → 即兴页专项）→ 交付**：`node script/render.mjs <任务运行区>/ --delivery=<YYYY-MM-DD-小标题>`；产物先全写运行区，校验与截图全过后才按白名单（`P*.html` + `P*.png` + `preview.png`）拷进交付目录；plan.json 与过程件留运行区，不进交付（§6）。

### 2.1 plan.json 规范（实例化输入的唯一格式）

**身份**：plan.json 是 AI 的唯一产出物，过程件（留任务运行区，不进交付）；render 把它转写为编辑器契约格式的 `fields.json`（同样先写运行区）——同一份数据，前者驱动填充，后者是给编辑器侧的**初稿值**。注意契约现状：**截至 v1.9，编辑器与 `pack.mjs` 都还不消费 `fields.json`**（读取初稿属 pageApp 未完成项），所以它写了不报错、也不影响打包。转写时 `fields.json` 的键统一为页面真实 `data-layer` id：repeat 条目短名映射回单元元素的 data-layer，并按克隆序号加 `-2/-3` 后缀（pageApp「fields.json」一节）。

```json
{ "style": "tech-blue",
  "delivery": "2026-11-15-ai工具盘点",
  "pages": [
    { "nn": "01", "layout": "N02-dialog-cover",
      "fields": {
        "title": "真正能让你<span class=\"hl\">少加班</span>的 AI 工具",
        "n02-img-1": "shots/a.png",
        "items": [ { "num": "01", "t": "Cursor · AI 编辑器", "d": "写代码快 5 倍" } ] } },
    { "nn": "02", "layout": "custom/双栏金句",
      "markup": "<div class=\"artwork-page\" data-artwork data-size=\"1080x1440\">…AI 受控即兴整页…</div>" } ] }
```

规则：
1. `fields` 键 = 母版槽位锚，分两层：**顶层文字槽 = {{槽名}} = data-layer id；图槽 = 图槽的 data-layer id**（三处同名）；**repeat 单元内用条目短名**（`n/t/d`…），clone 时 data-layer 自动加序号后缀。render 校验槽位一一对应——缺槽、未知槽、类型不符即停；
2. 字符串值可含受控富文本（仅 `span.hl` / `br` / `strong`）；**文案里的裸 `<` `>` 直接原样写**（`年收入 > 10 万`、`A < B`、`x<y 时`）——render 注入前转义为实体显示，只有形如 `<b>` / `<div class="x">` / `</div>` 的完整标签才硬停（`a<b>c` 本身就是合法标签形态，写成 `a < b`）；数组对应 repeat 槽，render 按母版注释克隆并校验区间（超出 ×min-×max 即停）；
3. 图片值 = 相对路径；render **同时**把图内嵌为 dataURL（交付页自包含）并把原件复制进运行区 `assets/` 作副本；杂乱图加 `"crop": "下 55%"` 或 `"left 30%"`（parseCrop 只收「方位 + 百分比」，不收 `object-position:` 字面值）；
4. 即兴页：`layout: "custom/<语义名>"`，`markup` 附整页根节点 HTML（**根类固定 `.artwork-page`**），须过形态校验；几何体检需显式 `--check-geometry`（见 §5）；
5. 填表前必须先读选中母版——不预判槽位、不虚构字段名；
6. `delivery`（可选）：交付目录路径，等价于命令行 `--delivery`；相对路径按当前工作目录解析，目录命名 `YYYY-MM-DD-<小标题>`（§6）。

### 3.1 就地限制（字数限值的口径）

母版说明头的「限制」行是**机器可读的**——render 解析 `≤N字` / `≤N字符` 做字数软校验，WARN 里的「字位」「字符」按本节口径算。填 plan 时用这套口径判断文案会不会超；写母版时怎么标定限值见 final/03「说明头规范」。

**两种写法，两种口径（不要混用）：**

| 写法 | 含义 | 用在哪 |
|---|---|---|
| `≤N字` | **视觉宽度**，1 = 一个汉字宽 | 标题/副题/正文/结论条/说明等以中文为主的槽 |
| `≤N字符` | **实际字符个数**（码点） | 编号/型号/路径/数字等 ASCII 短槽：`big-num`、`n`、`app`、`when`、`speed`、`model-id`、`shot-name` 等 |

> 不登记「多少个键用了哪种写法」这类派生数量——母版一改就漂移，口径本身才是规则。

**行数写法**：`code≤2行每行≤30字符`（无括号）由 render 校验两件事——行数不超、且每一行各自不超每行限值。**括号里的内容一律不解析**：`(2行)` 的行数、`(2行,每行≤7字)` 的每行值都只人审；要机器管就改写成上面的无括号写法。

`≤N字` 的宽度权重：**建模值 ≥ 脚本实测值**（100px 字号，canvas `measureText` 逐字符量 em 比例）。右列来自 `--font-report` 的真实输出，**实测三档 = serif 700 / sans 400 / mono 600**（本机命中 Songti SC / PingFang SC / Menlo，无 webfont 分片）；这是脚本唯一覆盖的档位，复现方式见本节「重测时机与顺序」第 2 步。

| 内容 | 记几个字位（建模值） | 实测（serif 700 / sans 400） |
|---|---|---|
| 汉字、全角标点 | 1 | 1.000em（三档逐字符一致，含 ，。、；：！？（）「」） |
| 英文大写 | 0.68 | 0.661（serif 700）–0.664（sans 400） |
| 英文小写 | 0.55 | 0.452（serif 700）–0.534（sans 400） |
| 数字 | 0.58 | 0.469（serif 700）–0.575（sans 400） |
| 半角标点/符号 | 0.45 | 0.255（serif 700）–0.324（sans 400） |
| 空格、换行、HTML 标签（`<span class="hl">`） | 0（去掉后数） | — |
| emoji、其他文字符号 | 1（保守按一个汉字宽） | — |

建模值 ≥ 上面区间上限 = **宁可早告警也不放过溢出**，代价是同长度英文多报一点宽度。例外：mono（Menlo）每字符一律 0.602em，比小写 0.55、数字 0.58、标点 0.45 都宽——**等宽槽**（编号/代码/路径）全部走 `≤N字符`，不受影响；新槽不要用 `字` 限制等宽字体。

**重测时机与顺序**（改字体必须先重测，否则限值全部作废）：

1. **先定字体契约**：本机字体栈（现状）还是随包 webfont。契约不定就别急着测——换一次字体，实测值全废。
2. **再量字宽**：`node script/render.mjs <任务运行区>/ --only=N01 --font-report` → 打印三套栈实测字宽与实际命中 face；把上表右列换成本机值，确认建模值仍 ≥ 实测。这是**只读诊断**（`--only` + `--font-report` 组合）：临时页跑完即删，不写 P 页/PNG/fields/manifest/preview，可在正式运行区直接跑，无需事后恢复。
3. **最后逐键量容器容量**（T6）：用真实最长文案试渲染，量每个容器实际能放多少字位，说明头「限制」的数值改写成「实测 − 余量」。

只有第 3 步依赖前两步。跳过 1、2 直接调限值 = 把某台机器的字面当成契约。

例：`title≤10字` 的中文能放 10 个汉字；同一个槽放英文可放约 20 个小写字母（`VSCode` = 3.5 字位，`management` = 5.0 字位，一个 10 字母单词只占半个汉字宽度）。**不要按单词计**（`VSCode` 记 1 会直接溢出），也**不要按 1 字母 = 1 字**（会把英文砍掉一半容量）。

- **容差**：超限 20% 以内只记 WARN 不拦（同一字号下偶发换行可接受）；WARN 会打印「宽度 X 超限（≤N 字位…）」或「字符数 X 超限（≤N 字符…）」，同时给出限值与容差上限，便于判断是改文案还是调限值。
- **限值取「实测 − 余量」**（新建/改母版时用最长真实文案试渲染量出容量）。逐档校准在施工台账 T6 进行中；未校准的槽，WARN 只作提示、不当作硬边界。

|---|---|---|---|
| **手机截图** | 竖长（≈9:19.5）、状态栏/圆角特征 | 套手机壳槽。**手机框由 render 单源内嵌**：`frame-img` 类装饰槽自动读取 `styles/assets/iphone-frame.png` 现场编码内嵌（缺文件即停） | 手机壳母版（tech-blue N04 等） |
| **窗口截图** | 顶栏/地址栏/标题栏特征，横版 | 图进窗口内容区槽位；原图自带边框的用无边框槽避免双框 | 各风格窗口类母版 |
| **干净内容图** | 主体明确、构图完整 | 直接用，槽位比例 cover 裁切 | 任意图槽 |
| **杂乱图** | 全屏截图/聊天长图/多区域 | AI 读图选区 → plan.json 写 `crop` 描述（`"下 55%"` / `"left 30%"` / `"bottom 40%"`），render 外包裁切容器 + CSS 定位实现 | 裁剪后进任意图槽 |

总则：PNG/JPEG/WebP；裁切由 CSS 机械完成，AI 不做像素级编辑，人审 PNG 是裁切质量最终把关；像素级精确裁剪（真改文件）=可选增强，v1 不做；形状严重不符换槽位/换母版，不硬塞。

### 3.3 字体策略（本机字体栈的实测与核对）

写母版侧的字体约束与理由见 final/03「字体规范」。本节只记跑图侧三件事：

- **声明与回退**：`--serif/--sans/--mono` 直接声明本机字体族，命中即用、未装按栈回退。
- **出页防御**：render 剥离 `@import` 行（正常情况下源 CSS 已无 @import）；生图自己的 CDP 截图不受外链限制。
- **随包分片**：`styles/assets/fonts/` 的 fontsource 分片未接入，日后启用按 TODO 附表立项。

**「本机字体栈」= 运行机器已装的字体，不是随包分发的字体。** 实测（macOS 本机，用 CDP `CSS.getPlatformFontsForNode` 读真实渲染 face）：

| 声明栈 | 本机实际命中 | 说明 |
|---|---|---|
| `--serif` = Noto Serif SC → Songti SC → Source Han Serif SC | **Songti SC** | 本机未装 Noto Serif SC，落到系统宋体（仍是衬线，字形与 Noto 有差） |
| `--sans` = Noto Sans SC → PingFang SC → Microsoft YaHei | **PingFang SC** | macOS 中文默认，命中第二顺位 |
| `--mono` = JetBrains Mono → SF Mono → monospace | **Menlo** | 前两者都未装，落到通用 monospace |

含义有两条，跑图前必知：① **出图字形与字宽由运行机器的已装字体决定**，同一份 plan 在装了 Noto 的机器与没装的机器上字面不同（换机出图需目检）；② 字数限值是**本机字面下的实测值**（见「就地限制」节），换机后需复核。

**核对命令**：`node script/render.mjs <任务运行区>/ --only=N01 --font-report` → 打印该页实际命中的 face、`@font-face` 声明/加载数、三套栈的实测字宽。这是**只读诊断**（`--only` + `--font-report` 组合）：临时页跑完即删，不写任何产物（P 页/PNG/fields/manifest/preview 全不动），可在正式运行区直接跑、无需事后恢复；不带 `--only` 则是出图时顺带体检。体检本身默认关闭（每页多一次全量 DOM + 逐文字节点往返），不进常规出图。三处用途：换机出图前确认命中的是预期 face；接入 webfont 后抓「声明了却 0 个加载 → 静默系统回退」；T6 重测字宽。编辑器导出走的是**那台机器**的本机字体，所以在 pageApp 机器上打包前先跑一次同一命令，比事后看 PNG 猜字形可靠。

**字体契约是 T6 的前置**：本机栈还是随包 webfont 未定之前不做逐键校准——换一次字体，所有实测限值作废。

未接入的 fontsource 分片只有 **400 单字重**（Noto Serif SC 101 片 + Playfair Display 4 片 = 105 片），而母版标题用 700/900——日后若启用 webfont，必须先补粗体字重分片，否则标题会合成假粗或回退。

## 4. 选型、画廊与受控即兴

### 4.1 选型链

1. 人/AI 读 `style-picker.md` 定风格；
2. AI 读 `styles/<风格>/catalog.md`，按语义组+四栏选母版——**输入含素材类型分布（④）**：有手机截图的页才考虑手机壳母版；
3. 精确条数/字数从选中母版的 repeat 注释与说明头读取（⑦ 填表前）。
- **两层职能，不重复配置**：catalog 的「字数语义」 = 从母版 repeat 注释蒸馏出的**选型语义**（判断内容体量合不合脚）；精确数字只在母版注释（唯一配置点）——**catalog 管选型判断，repeat 管填充校验**。
- catalog 与母版说明头**同源同步**（改一处另一处跟改；靠入库纪律，v1 无自动校验）。
- **catalog 条目格式**（四栏，一段一条）：

```
N10 工具清单
适合：3-8 条量级的工具/资源推荐，左文右图双栏
不适合：每条需要长说明（d 只有一行）；纯图片展示
可以变：右栏图格可减；编号样式可换
字数语义：标题两行内；条目名≤10 字（精确联动预算见母版 repeat 注释）
```

### 4.2 受控即兴（三级阶梯）与转正

- **即兴三级阶梯（绝大多数任务停在 L1/L2，L3 是罕见兜底）**：
  - **L1 直接套用**：catalog 能选到 → 用母版（默认路径）；
  - **L2 母版为底微调**：接近但不完全合脚 → 以某母版为底做局部增删（删可选槽位、条数在 repeat 区间内、槽位换图）；
  - **L3 受控即兴**：无合脚母版 → 用 style.css 既有类组合整页（layout 登记 `custom/<语义名>`）。
- **内容约束**：即兴只调整「版式对内容的呈现」，文案仍忠于素材提炼结果——**禁大幅改写内容迁就版式**；需要大改内容 = 回炉②重提炼，不是即兴能解决的事。
- 即兴边界（不变）：只用 style.css 既有类 + 遵循 design-system.md；**禁止内联样式、自造 CSS 变量、新类名**（新类=风格演进=用户过目改 style.css 并登记 design-system）。
- 即兴页校验升级：形态校验必查（根节点 / 禁区属性 / data-layer 唯一）；几何体检需显式传 `--check-geometry`，且只对 custom 页执行（§5）。
- 转正：同名 `custom/<名>` 累计 ≥2 次 → AI 提示建议入库 → 按 final/03 重整（补标记/占位符/限制注释/入 templates.html+catalog）→ 用户目检 → 真实任务回归一次。转正不是复制粘贴当次产物。
- 即兴两次不满意同一内容 → 直接走转正管道，不无限即兴。

### 4.3 画廊（templates.html 三合一）

templates.html 既是仓库也是画廊：顶部导航（语义组锚点）+ 风格看板（色板/字体/字号/画布规格，与 style.css 同源）+ 分组区头 + 母版纵向平预览（带说明头）。浏览器打开即所见。**不用 iframe**：iframe 需每母版独立文件，与「单文件平铺」的存储方式矛盾。人审细节开画廊；当次出图总览看 `<交付目录>/preview.png`（§6）。

## 5. render 实例化器规格

| 项 | 内容 |
|---|---|
| 输入 | `<任务运行区>/plan.json` + 素材图片（相对运行区）；`--delivery` 或 plan.delivery 指定交付目录 |
| 步骤 | 按 layout 从 templates.html 抽 section（custom 页直用 AI markup）→ **fillSection 固定填充顺序**：repeat 从后往前克隆 → 图槽只替换 src（`data-slot/data-layer/data-label/data-ratio` 原样保留 + 父容器补 `data-filled`）→ 含手机框槽的页才内嵌手机框（读 `styles/assets/iphone-frame.png` 现场编码）→ 顶层文字槽 → 多余字段与 `{{` 残留校验 → crop 执行 → style.css 内联（防御性剥离 `@import`）→ 图片内嵌 dataURL + 原件复制进运行区 `assets/` 作副本 → 包独立壳写 `P<nn>-<名>.html` → Chrome 逐页截图 1080×1440 → 生成 preview.png 总览 → 生成 `editor.manifest.json` + `fields.json` → **全部写入任务运行区** → 三层校验与截图全过 → 白名单拷贝交付目录（§6） |
| 输出 | 运行区：上述全部过程件与产物；交付区：默认 `P*.html` + `P*.png` + `preview.png`，`--with-editor` 追加 `fields.json` / `editor.manifest.json` / `assets/` |
| 硬校验（即停） | `{{` 残留 / 图片缺失或格式不符 / 图槽 `<img data-slot>` 缺 data-layer / 根节点与画布确认（custom 页含根类与禁区属性）/ `data-layer` 全页唯一 / 必填槽为空 / plan 字段与槽位对不上 / layout 在 templates.html 不存在 / repeat 区间越界 / 交付目录已存在且非空（除非 `--force`）、不是目录或等于任务运行区 / `--delivery` 空值 / `--only` 空值或与交付互斥 / 手机框资产缺失（含手机框槽的页） |
| 软校验（WARN） | 字数超限（解析限制注释比对）/ 图片与槽位比例差异大（提示裁切量，**只判 PNG 尺寸头**，JPEG/WebP 不判）·（catalog 与说明头同源同步 v1 未自动校验，靠入库纪律保证） |
| 即兴页专项 | 形态校验（根节点 `.artwork-page` + `data-artwork` + `data-size` / 无禁区属性 `position:fixed`、`@media`、`<script>`、`animation`、`transition` / `data-layer` 唯一）+ `--check-geometry`（显式开启时才做几何体检：画布溢出与元素越界，仅 custom 页） |
| 地基 | `script/render.mjs` = **生产环境固定脚本**（唯一实例化器）+ `script/shared/`（find-chrome 定位浏览器、cdp 调试桥） |

**「三层校验」= 上表三行**：硬校验（即停）→ 软校验（WARN）→ 即兴页专项（形态必查 / 几何体检需显式开）。硬校验那一行是**摘要**，逐条报错条件以 `script/render.mjs` 实现为准；`SKILL.md` 与流程图里出现的「三层校验」都是这个意思，不另加层。

> **受限环境适配（Chrome 沙箱）**：容器 / root / CI / macOS 沙箱下，browser 进程能起来但 renderer 一起就被杀，表现为调试管道秒关、stderr 只有 crashpad 噪声（看不到 `No usable sandbox`）。`launchBrowser` 启动后用 `data:` URL 真导航一次做冒烟，失败即自动加 `--no-sandbox` 重试**一次**（日志出现 `⚠ Chrome 首次启动失败…`）；已显式开 `noSandbox` 时不再重试，避免掩盖真实错误。

> **手机框单源（交付口径）**：`styles/assets/iphone-frame.png` 是唯一源。render 的 `getFrameDataUrl()` 读取该 PNG → 编码成 dataURL → 替换母版 `frame-img` 槽的 src，把框图直接内嵌进交付页；**PNG 本体不进交付目录**。画廊以 `../assets/iphone-frame.png` 相对路径引用同一份文件。

## 6. 交付（三级目录分离）

| 层级 | 位置 | 运行期写入 | 放什么 |
|---|---|---|---|
| ① 技能安装目录 | 本仓库（`SKILL.md` / `styles/` / `script/` / `final/`） | **只读，零写入** | 只读资产与代码；不写任务产物、不写临时脚本 |
| ② 任务运行区 | agent 临时工作区 `runs/<任务>/`（gitignore） | 读 + 写 | `plan.json`、原始素材、`shots/`、日志、`P*.html`、`P*.png`、`preview.png`、`assets/`、`fields.json`、`editor.manifest.json`（另有 `_preview.html`：拼总览用的临时页，截完即删） |
| ③ 交付目录 | 用户选中的工作区；未指定则用 agent 默认任务文件夹 | 只写白名单 | 见下方标准包 |

- 交付目录由调用方命名 `YYYY-MM-DD-<文章小标题>/`，经 `--delivery=<路径>` 或 `plan.json` 的 `delivery` 字段给出；相对路径按当前工作目录解析。
- **顺序**：先写运行区 → 三层校验与逐页截图全部通过 → 再按白名单拷贝。任何硬错误或截图失败都不产出交付目录。
- **不覆盖**：目标目录已存在且非空即停；同一任务重跑加 `--force`（只覆盖白名单文件，不删其它内容）。目标路径若已存在但不是目录，直接报错。
- **`--only` 仅调试**：只出指定页且只写运行区，与 `--delivery` / `plan.delivery` 互斥；正式交付必须跑完整页数，否则会把单页的 preview/manifest/fields 混进交付包。
- 标准包（默认白名单）：

  ```
  YYYY-MM-DD-文章小标题/
    P01-封面.html   P01.png
    P02-清单.html   P02.png
    …
    preview.png     （当次总览拼图，人审第一眼）
  ```
- `plan.json`、素材副本、过程件一律留运行区，不进交付。交付页 HTML 自包含（CSS 内联、图片 dataURL 内嵌），故 `assets/` 只是副本，默认不进交付。
- `--with-editor` 追加：`fields.json` + `editor.manifest.json` + `assets/`（编辑器材料；pageApp 尚未消费 `fields.json`，除排错外非必需）。
- 编辑器微调：`cd <pageApp 仓库>/demo && node pack.mjs "<含 manifest 的目录>"`（可指向任务运行区，或带 `--with-editor` 的交付目录）→ `covers-edit.html`。pageApp 仓库本机两处：Windows `D:\AI\pageApp\demo`｜macOS `/Users/shay/Code/AI/pageApp/demo`。此命令依赖本机 pageApp，生产安装不可用——待开发项登记于 TODO 附表（SKILL.md 对应处标【待开发】）。
  **已知差异（交接时要说清）**：编辑器把「图片适配方式」存成自己的图层状态（默认 `cover`），打开页面即给每个 `<img>` 写内联 `object-fit`，覆盖母版的 `data-fit`。是否造成损失取决于图与槽是否同比例——全库唯一 `contain` 槽（N29 二维码，1:1）放 1:1 的二维码时两者渲染一致、无损失；往它塞非等比图才会被裁（实测 4:3 进 1:1 槽横向损失 25%）。规则：contain 槽只放同比例图。取舍与提案见 final/03「扩展属性与契约的同步关系」。
